# 쓰지 않는 단계를 걷어내고, 프롬프트를 복사 대신 실행으로 바꾼 날

> 새벽에는 create → curate → apply 로 설계했지만 실제로 돌린 적이 없는 단계를 전부 삭제해 생성·수정·분할 세 프롬프트로 개념을 좁혔다. draft/stable 상태값도 코드 위치와 완전히 중복이라 active 하나로 줄였다. 낮에는 그렇게 남은 프롬프트를 CLI에 복사해 붙여넣던 마지막 손동작마저 없애고, 갤러리 안에서 Claude Code를 헤드리스로 띄워 실행까지 끝내는 즉시 실행을 붙였다.

## 배경

ui-harness 갤러리는 원래 컴포넌트를 만들고(create), 큐에 쌓아 선별하고(curate), 통과한 것을 staging에서 정식 위치로 승격하는(apply) 파이프라인으로 설계돼 있었다. 그런데 실제로 curate와 apply를 돌릴 여유가 한 번도 없었다. 리뷰 큐는 늘 비어 있었고, draft 상태의 컴포넌트는 90개까지 쌓였다.

쓰지 않는 단계가 UI와 문서에 남아 있으면 그건 "해야 하는데 안 한 일"처럼 읽힌다. 매번 갤러리를 열 때마다 빈 리뷰 큐가 시선에 걸리고, 카드마다 draft 배지가 붙어 있으면 마치 미완성인 것 같다. 새벽 작업의 동기는 그 빚을 인정하고 지우는 것이었다. 남는 것은 결국 생성 · 수정 · 분할 세 프롬프트뿐이니, 개념을 거기까지 좁히기로 했다.

낮에는 반대 방향으로 갔다. 세 프롬프트로 좁히고 나니 이번엔 그 프롬프트를 쓰는 동작 자체가 눈에 걸렸다. 버튼을 눌러 복사하고, 터미널로 창을 옮기고, 붙여넣고, 결과를 보러 다시 브라우저로 돌아온다. 프롬프트가 이미 실행 가능한 형태로 완성돼 있는데 옮기는 일만 사람이 하고 있었다. 그래서 갤러리 안에서 바로 spawn하기로 했다.

## 핵심 내용

### 개별 작업 기록 (시간순)

- 전역 스크롤바를 한 벌로 통일, 클래스 수동 부착 폐기
  - 다크 모드에서 스크롤바가 "스타일이 안 먹은" OS 기본 모양으로 보이던 원인을 찾았다. Chrome 121+ 는 요소에 `scrollbar-width`/`scrollbar-color` 가 있으면 그 요소의 `::-webkit-scrollbar` 를 통째로 무시한다. 두 방식을 같이 선언해 둔 탓에 webkit 쪽(둥근 thumb, hover 확장, 6px 폭)이 전부 죽어 있었다.
  - 죽은 `::-webkit-scrollbar` 블록과 `html` 전용 중복 규칙을 걷어내고 `:where(*)` 한 곳만 남겼다. specificity 가 0이라 모든 스크롤 영역에 저절로 걸린다. 새 패널을 만들 때마다 클래스를 붙일 필요가 없어졌다.
  - thumb 를 전경색 25%에서 32%(hover 55%)로 올려 다크에서 트랙과 붙어 보이던 문제를 없앴다. 손으로 붙이던 `.custom-scrollbar` 는 정의와 사용처 6곳에서 전부 제거했다(잔여 0).

- 상세 케밥에 분할 프롬프트 복사 추가
  - 컴포넌트가 한 덩어리로 비대해졌을 때 쓰는 프롬프트다. 수정 프롬프트와 갈리는 지점은 결과물의 성격이다. 수정은 컴포넌트 하나를 고치고 끝나지만, 분할은 조각 엔트리를 새로 만들고 원본을 그 조각들의 조립으로 바꾼다. 원본이 단일에서 composite 로 바뀌는 사실이 속성(`composedOf`)과 히스토리에 남아야 갤러리에서 관계가 보인다.
  - 프롬프트 절차는 분석(분할이 이르면 멈추고 보고) → 조립 단위 정의(코드보다 먼저 이름·역할·props) → component-create 프로토콜대로 조각 생성 → 재조립(공개 API 불변) → 위계 정리 순이다.
  - 메뉴에서는 수정 아래에 뒀다. 덜 쓰이고 되돌리기 어려운 쪽이라 기본으로 손이 가는 자리를 내준다.

- 상세 우상단 재배치, 프롬프트 3종을 아이콘 그룹으로
  - 프롬프트가 3종이 되면서 케밥에 묻혔고, 꺼내 놓자니 라벨 3개가 줄을 다 먹었다. 셋 다 "이 컴포넌트로 무엇을 시킬 프롬프트인가"라는 같은 축의 변형이라 한 덩어리로 묶고 아이콘으로 갈랐다. 배치는 핀 · [통합|수정|분할] · Storybook · 케밥이다.
  - 아이콘은 Copy(가져다 쓰기) / Wand2(고치기) / Split(쪼개기)로 형태를 확연히 갈랐다. 수정에 펜슬이 아니라 요술봉을 쓴 건 프롬프트가 손으로 고치는 게 아니라 AI 에게 시키는 것이기 때문이다.
  - 툴팁에는 이름이 아니라 용도를 적었다. "수정 프롬프트 복사"라고만 하면 무엇이 다른지 여전히 모른다. ButtonGroup 이 h-8/h-10 만 있고 네이티브 title 만 받아 툴팁 UI 를 못 붙이기에 세그먼트를 직접 짜서 높이를 h-9(36px)로 맞췄다.

- 리뷰 데스크에도 헤더 검색, 탭 전환 폭 출렁임 해소
  - 리뷰만 검색을 등록하지 않아 검색창이 통째로 사라졌고, 헤더가 w-fit pill 이라 폭이 695에서 298로 줄었다 돌아왔다. 여기서 찾을 대상은 지금 보고 있는 큐 안의 항목이라, 선택하면 `?focus=` 로 큐 안에서 옮겨 가게 했다(상세로 튀어 큐를 벗어나지 않는다).
  - `useReviewQueue` 의 focus 동기화를 양방향으로 넓혔다. 반대 방향(idx→URL)은 replaceState 라 NAV_EVENT 를 안 쏘므로 루프가 생기지 않는다.

- 타임라인 뼈대를 하나로, 세 곳이 같은 레일을 쓰게
  - 코멘트, 컴포넌트 이력, 페이지 이력이 각자 ol/li 와 점·연결선을 그리고 있었다. 셋 다 "점 하나에 한 사건, 그 옆에 누가·언제·무엇"이라는 같은 형태인데 간격과 점 크기가 조금씩 어긋나, 같은 패널에 나란히 서면 다른 리듬으로 읽혔다.
  - 리듬만 `staging/timeline` 으로 모으고 내용은 children 에 맡겼다(Timeline · TimelineItem · TimelineMeta · TimelineBody). 각자의 고유 기능(복원 컨트롤, stagger 등장, 인라인 수정)은 그대로 남는다.
  - `@maxflow/ui/staging/*` 는 디렉토리 index.ts 로 해석되므로 index 도 함께 뒀다. 빠뜨리면 typecheck 는 tsconfig paths 로 통과하는데 Vite 만 import 를 못 찾는다.

- timeline 조각을 레지스트리에 등록, 분할 5단계 마무리
  - 타임라인 통합으로 comment-timeline 이 단일에서 조각을 조립한 composite 가 됐는데, 그 위계가 레지스트리에 없어 갤러리에서는 여전히 단일로 보였다. 새벽에 만든 분할 프롬프트의 3단계와 5단계를 그대로 밟아 정리했다.
  - timeline 을 component-create 프로토콜대로 정식 엔트리로 등록했다(데모·스토리·카드 썸네일 + entry). category 는 System 이다. 자체로 완결된 UI 가 아니라 다른 타임라인들이 공유하는 구조 프리미티브이기 때문이다.

- 리뷰 데스크·curate·apply 제거, 생성/수정/분할로 일원화
  - 리뷰 데스크를 전면 삭제했다. 라우트 6파일, 상단 네비 항목, 큐 뱃지, "리뷰로 돌아가기" 버튼, 상세의 `reviewActive`/`inReviewQueue` prop, 수정 프롬프트의 `via:"review"` 분기까지 전부다.
  - 서버 API 에서 `/api/review-queue` 와 `/api/decisions` 를 제거했다(복원 API 는 히스토리 기능이라 유지). component-curate·component-apply 스킬과 review-queue.json·decisions.json 도 삭제했다.

- draft/stable 을 active 하나로, 승격 개념 제거
  - status 가 코드 위치와 100% 중복이었다. draft 90개 = `src/staging/` 90개, stable 25개 = `src/` 25개. 승격 파이프라인을 접자 단계 구분이 뜻을 잃었고, 위치가 이미 SoT 라(import 경로도 `files[0].path` 로 정한다) 상태로 또 적을 이유가 없었다.
  - EntryStatus 를 `draft|stable|merge-candidate|deprecated` 에서 `active|deprecated` 로 줄이고 엔트리 115개를 일괄 전환했다. 남은 뜻은 "쓸 수 있나" 하나뿐이다.
  - StatusBadge 는 폐기만 표시한다. 기본이 쓸 수 있는 것이라 active 에 배지를 달면 모든 카드에 같은 딱지가 붙어 아무 정보도 못 준다. 승격 유틸과 PromotionBadge·PromotionRibbon 도 삭제했다.

- 문서에서 curate·apply·승격 개념 정리
  - 코드에서 걷어낸 개념이 문서에 남아 있으면 역시 "해야 하는데 안 한 일"처럼 읽힌다. component-create GUIDE 에서 승격 전제로 쓰던 문장을 경로 기준으로 고쳐 썼다(`files[0].path` 가 위치와 import 경로의 단일 판단원). install-skills 와 skills/README 에서도 curate·apply 를 설치 대상에서 뺐다.

- 수정 프롬프트 요청사항 섹션을 맨 아래로 이동
  - CC 나 Codex 에 붙여넣으면 긴 본문이 `[Pasted text #XX +XX lines]` 로 접힌다. 요청사항을 마지막에 적는 편이 접힌 뒤에도 확인하기 쉽다.

- 컴포넌트 갤러리에서 갤러리로 네이밍 확장
  - 포트 9221 앱이 컴포넌트·페이지 플레이그라운드·흐름 3영역으로 확장됐는데도 런처 라벨과 탭 타이틀, 온보딩 안내가 여전히 "컴포넌트 갤러리"로 좁게 표현되고 있었다. 컴포넌트 목록 화면 자체의 타이틀은 그대로 두고 나머지만 "갤러리"로 통일했다.

- 페이지 플레이그라운드 헤더 프롬프트 복사를 구현용으로 분리
  - 헤더의 "프롬프트 복사"가 사이드바의 "피드백 프롬프트 복사"와 동일한 `buildPageFeedbackPrompt` 를 호출해 완전히 같은 텍스트를 복사하고 있었다. 헤더는 페이지 구조·사용 컴포넌트·import 경로를 담아 `@maxflow/web` 에 처음부터 구현할 수 있게 하는 `buildPageImplementPrompt` 로 분리했다.

- gallery.md 에 페이지 플레이그라운드·흐름 섹션 보강
  - `/pages`, `/flows` 관련 라우트·API·데이터 저장 위치가 문서에 전혀 없어 컴포넌트 갤러리 부분만 있는 것처럼 보였다. 실제 코드를 근거로 라우트 표, API 표, 데이터 스키마, 스킬 연동 흐름을 추가했다.

- 피드백 팝오버와 타임라인 경계선 대비 개선
  - FeedbackComposer 는 `bg-st-muted` + `border-st-border` 조합이 라이트와 다크 모두 캔버스와 명도차가 거의 없어 뜬 표면의 경계가 안 보였다. `bg-st-popover` + `border-st-foreground/15` 로 교체했다.
  - Timeline 연결선(`bg-st-border`)도 같은 이유로 라이트에서 사실상 안 보여 세 종류 타임라인 전부에서 레일이 끊겨 보였다. `bg-st-foreground/30` 으로 바꿔 항상 보이는 선으로 만들었다.

- 피드백 작성기 textarea 외곽선 제거, 대상 칩은 배경으로 구분
  - textarea 의 쉬는 상태 테두리를 투명으로 바꿔 표면과 이어져 보이게 했다. 대상 칩은 작성기 표면이 st-popover 로 바뀌며 `bg-st-card` 와 값이 같아져 배경만으로는 묻혔다. 테두리 대신 `bg-st-muted` 배경으로 구분한다.

- 피드백 textarea 플랫화 + 팝오버 오픈 시 자동 포커스 신뢰성 개선
  - 요청에 따라 포커스 테두리까지 없애 완전히 플랫하게 만들었다.
  - AnchoredPopover 의 자동 포커스가 사실 한 번도 동작하지 않고 있었다. children 의 autoFocus 는 첫 마운트 시 한 번만 시도되는데, 그 시점엔 위치 계산 전이라 `visibility:hidden` 상태다. 숨은 조상 아래 요소는 브라우저가 `focus()` 를 거부한다. 위치가 잡혀 실제로 보이게 된 시점에 패널 안 textarea 를 마운트당 한 번만 다시 focus 하도록 고쳤다.

- textarea 자체 패딩 제거, 코멘트 케밥 버튼의 행 높이 왜곡 수정
  - 테두리가 없어 박스로 안 보이니 칸 자체 패딩을 빼 표면의 `p-3` 에 맞췄다. 칩과 버튼 줄이 좌우로 나란해진다.
  - CommentTimeline 의 케밥 트리거(28px)가 작성자 줄 텍스트(약 11.5px)보다 훨씬 커서, `items-start` 행이 텍스트가 아니라 케밥 높이만큼 벌어져 있었다. 점과 첫 줄과 본문 사이 간격이 Timeline 데모와 달라 보이던 원인이다. `-my-2` 로 레이아웃상 차지하는 높이만 텍스트에 맞추고 실제 클릭 영역은 그대로 뒀다.

- SearchPalette 에 renderPreview 추가, 컴포넌트 지목 팔레트에 정적 스냅샷 미리보기 연결
  - `renderPreview(item)` prop 을 주면 활성 항목 옆에 미리보기 열이 하나 더 붙는다. 안 주면 기존처럼 단일 열 그대로라 다른 소비처(FlowDetailRoute)는 회귀가 없다.
  - PagePlaygroundRoute 의 ComponentPicker 는 갤러리의 정적 카드 프리뷰를 그대로 재사용했다. 라이브 데모를 그 자리에 마운트하지 않으므로 자체 포탈이나 상태를 가진 컴포넌트와 충돌할 걱정이 없다.

- 상단 헤더 Dock 분리와 이어진 시각 조정 네 번
  - 페이지 전환 네비와 유틸리티(테마·도움말·검색)를 별도 pill 로 나누고, 테마변경과 도움말 버튼에도 다른 아이콘 버튼과 동일한 Tooltip 을 붙였다.
  - 페이지 전환 Dock 에 ButtonGroup 시각 언어(전체높이 세로 구분선, 세그먼트 색칠)를 이식했다가, 무거워 보여 개별 원형 아이콘 버튼으로 되돌렸다. 유틸 Dock 은 검색을 왼쪽, 터미널·테마·도움말을 오른쪽으로 재배치했다.
  - 두 헤더 pill 의 `shadow-lg` 를 걷어내 더 플랫하게 만들고 라이트 모드 활성 탭 톤을 보정했다. 그런데 `.header-elevate` 가 `data-scrolled="true"` 일 때만 좁은 그림자로 바뀌는 규칙이 있어, 방금 뗀 `shadow-lg` 와 합치면 스크롤 전엔 그림자가 아예 없었다. 스크롤 조건을 없애고 항상 크게 퍼지는 고정값 하나로 바꿨다가, 너무 진하다는 피드백을 받아 퍼짐은 유지하고 불투명도만 절반으로 낮췄다.

- 카드와 칩의 색·밀도 정리
  - 라이브러리 카드마다 "프롬프트 복사" 텍스트 버튼이 반복돼 카드 하단이 붐볐다. iconOnly 로 바꿔 Copy 아이콘만 남기고 라벨은 툴팁으로 옮겼다.
  - 배치 지목 칩이 `bg-st-primary`(인디고)를 써 작성기 카드 안에서 유일하게 색이 들어간 요소였다. `bg-st-foreground/10` 잉크 틴트로 바꿔 대상 칩보다 한 단 진한 무채색 톤으로만 구분하게 했다.
  - 플레이그라운드 사이드바 탭 폰트는 한 단 줄이고, 툴바 안내 문구는 한 단 키웠다. 각각 좁은 폭 대비 커 보였고 반대로 너무 작았다.

- 컴포넌트 상세 속성 패널 표현 개선
  - InfoTable 의 값 폰트를 등간격에서 일반 sans 로 바꾸고, "토큰" 값은 comma-list 대신 Badge 칩으로, import 와 props 값은 CodeBlock 의 `tokenize()` 를 재사용해 신택스 하이라이트가 붙은 코드체로 표현했다.
  - 이어서 TS 기준으로 색을 더 정확히 맞췄다. import 값은 문자열 리터럴로 감싸 기존 문자열 색을 그대로 타고, props 값(`name?: type(detail)` 요약 표기)은 전용 파서 `tokenizePropsSignature()` 를 추가해 타입 이름은 타입 색, enum/token 상세와 따옴표 붙은 프로퍼티 키는 문자열 색으로 표시한다.

- 컴포넌트/페이지 프롬프트 즉시 실행 기능 추가
  - 수정·분할·피드백 프롬프트를 복사해 CLI 에 붙여넣던 흐름을, 갤러리 안에서 바로 Claude Code 를 헤드리스로 spawn 해 실행까지 끝내는 "즉시 실행"으로 대체했다.
  - vite 미들웨어에 `/api/agent/*`(spawn·kill·stream·runs)를 추가하고 CLI 별 어댑터 인터페이스로 분리했다(v1 은 Claude Code 만). 큐 1개 동시실행에 FIFO, `--resume` 이어서 실행, SIGTERM 후 SIGKILL 중단을 넣었다. `bypassPermissions` 의 파급력 때문에 갤러리 자기 출처만 허용하는 Origin 검사를 신규 도입했다.
  - 네비에 터미널 아이콘을 두고 실행 중 점멸, 완료 시 성공/실패 색 전환을 붙였다. 하단 팝오버에 아코디언 로그를 터미널 톤으로 띄우고, 완료 시 프리뷰를 하이라이트 플래시한다. 요청사항 입력은 공용 FeedbackComposer 를 재사용했다.
  - 어댑터 실측 스키마 기반, 큐 동시성, 라인버퍼링, 프롬프트 회귀까지 30개 파일 180개 테스트를 붙였다. 그 과정에서 gallery/lib 테스트가 실행조차 안 되던 vitest.config.ts include 누락도 같이 고쳤다. 부가로 테마 전환 단축키(⌘⇧L)를 추가했다.

- 갤러리 루트 리다이렉트 + 앰비언트 배경 그라데이션/그리드
  - `/` 진입 시 `/components` 로 replace 리다이렉트하고, 좌상단과 우하단에 은은한 명도 그라데이션 글로우와 연한 선 그리드를 전역 배경에 추가했다. 상세 미리보기 캔버스도 자기 고유 배경 위에 같은 레이어를 얹어 톤을 통일했다.

- 컴포넌트 지목 팔레트 푸터·미리보기 개선
  - SearchPalette 키 힌트 푸터가 목록 열에만 걸려 있어 오른쪽 미리보기 열까지 안 이어지던 것을 바깥 세로 스택으로 옮겨 전체 폭으로 걸치게 했다.
  - 미리보기 카드 하단에 히스토리 기반 "최근 수정"과 상세 페이지 "바로가기" 링크를 추가하고, 300줄 소스 크기 정책에 맞춰 ComponentPreviewPane/EntryGlance 를 별도 파일로 분리했다.

- 검색 팔레트 인터랙션을 네 번에 걸쳐 다듬음
  - 행 클릭이 즉시 `onSelect` 를 커밋하던 것을 hover 와 동일한 "활성화(미리보기)"만 하도록 바꾸고, 실제 커밋은 활성 행에 나타나는 원형 보내기 버튼에서만 일어나게 분리했다. 클릭 한 번으로 실수로 추가되던 문제를 없앤다.
  - 그런데 hover 가 곧장 active 로 승격돼 "지금 마우스가 있는 곳"과 "실제로 선택된 행"이 똑같이 보였다. hover 는 순수 CSS(연한 회색, JS 상태 변화 없음)만 얹고, 진한 강조와 보내기 버튼 노출은 클릭·키보드 커서로만 정해지는 active 에서만 나타나게 분리했다. 미리보기 패널도 hover 가 아니라 active 를 따른다.
  - 행을 클릭하면 포커스 없는 요소라 브라우저 기본 동작으로 검색 입력의 포커스가 빠져나가 이후 방향키가 먹지 않았다. 행과 보내기 버튼의 mousedown 에 preventDefault 를 걸어 입력 포커스를 유지하고, 실제 mousedown→click 순서를 재현하는 회귀 테스트를 붙였다. 오른쪽으로 옮겼던 보내기 버튼은 왼쪽 원형 그림 자리에서 화살표로 바뀌게 되돌렸다.
  - renderPreview 가 있는 소비처는 설명이 이미 미리보기 카드에 나오므로 행에서 설명 줄을 생략한 컴팩트 모드로 표시한다. 섹션의 limit 과 "모두 보기" 링크 방식은 무한스크롤로 대체했다.

## 정리

하루가 둘로 갈렸는데, 방향이 정반대로 보이면서 실은 같은 이야기였다.

새벽은 빼는 쪽이었다. curate 와 apply 는 잘못 설계된 게 아니다. 파이프라인으로서는 옳았고, 다만 그걸 돌릴 사람이 없었을 뿐이다. 그래서 "언젠가 쓰겠지" 하고 남겨두기 쉬운데, 남겨두면 비용을 계속 낸다. 빈 리뷰 큐가 매번 시선에 걸리고, 90개 카드에 draft 배지가 붙어 전부 미완성처럼 읽힌다. **쓰지 않는 단계는 중립이 아니라 마이너스다.**

특히 draft/stable 을 지운 판단이 오래 남는다. status 필드가 있고 값이 잘 채워져 있어서 문제로 안 보였는데, 세어 보니 draft 90개가 정확히 `src/staging/` 90개였다. 완전한 중복이었다. 두 개의 진실이 있으면 언젠가 어긋나고, 어긋나면 어느 쪽이 맞는지 판단할 근거가 없다. 위치는 import 경로를 결정하니 이미 SoT 다. 그러면 status 는 파생 정보이지 저장할 것이 아니다. 배지도 같은 논리로 정리했다. 모든 카드에 붙는 딱지는 정보량이 0이라, 기본값이 아닌 것(폐기)만 표시하는 게 맞다.

낮은 더하는 쪽이었지만, 더한 것은 기능이 아니라 사람 손이 하던 일의 제거였다. 프롬프트는 이미 "그대로 붙여넣으면 실행되는" 수준까지 다듬어져 있었다. 남은 건 복사하고, 창을 옮기고, 붙여넣고, 돌아오는 왕복뿐이었다. 그 왕복이 자동화 가능한 순간 그건 기능이 아니라 잔여물이다. spawn 을 붙이면서 `bypassPermissions` 의 파급력 때문에 Origin 검사를 새로 넣은 것도 같은 맥락이다. 편의를 늘리면 그만큼 경계를 그어야 한다.

되돌린 것도 두 번 있었다. Dock 을 ButtonGroup 세그먼트로 만들었다가 무거워 원형 버튼으로 복원했고, 그림자를 걷어냈다가 스크롤 전 그림자가 사라지는 부작용을 만나 고정값으로 다시 넣었다가 진하다는 피드백에 불투명도만 낮췄다. 시각 조정은 실측하기 전엔 모른다는 걸 반복해서 배운다. 검색 팔레트도 클릭 커밋을 미리보기로 바꾸자 hover 와 active 가 구별이 안 되는 문제가 새로 생겼고, 그걸 고치자 이번엔 포커스가 빠져 방향키가 죽었다. 인터랙션 하나를 바꾸면 인접 상태가 줄줄이 딸려 나온다. 이번엔 mousedown→click 순서까지 재현하는 회귀 테스트를 붙여뒀다.
