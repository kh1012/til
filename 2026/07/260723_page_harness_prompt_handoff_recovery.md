# 목업 갤러리를 핸드오프 도구로: 프롬프트 라이프사이클과 저장 복구

> 프리뷰 정합성에서 시작해 프롬프트 복사·편집기 저장을 취소 가능하고 복구 가능한 경계로 다시 그린 하루.

## 배경

page-harness 갤러리는 Puck 기반 페이지 목업 도구다. 그동안은 "안에서 예쁘게 만드는 것"에 집중해 왔는데, 이날의 축은 그 바깥이었다. 목업에서 확정한 구조를 어떻게 실제 `@maxflow/web` 코드로 넘길 것인가, 그리고 그 과정에서 사용자가 작업을 잃지 않게 할 것인가.

그래서 하루가 크게 세 덩어리로 갈렸다. 오전엔 프리셋을 고르는 첫 화면의 정보 밀도와 프리뷰 정확도, 오후엔 삽입·템플릿 저장 동선과 그 과정에서 드러난 접근성 회귀, 저녁부터 밤까지는 프롬프트 복사·편집기 저장·차트 측정 같은 "비동기 라이프사이클" 전반이었다. 마지막 축이 제일 오래 걸렸고, 배운 것도 거기 몰려 있다.

## 핵심 내용

### 개별 작업 기록 (시간순)

- update (프리셋 피커 재구성)
  - 프리셋 모달을 2열 카드 그리드에서 리스트형 카드로 바꿨다. 썸네일을 왼쪽에 두고 설명을 3줄까지 보여주는 형태다. 썸네일 프레임은 `h-16` 고정 높이 대신 `aspect-[16/10]`로 고정해, 세로로 긴 구조의 프리셋도 찌그러지지 않고 읽히게 했다.
  - 팝오버에서 `transform-gpu will-change-transform-opacity`를 걷어냈다. 상시 GPU 레이어 승격은 이득 없이 합성 레이어만 늘린다.

- 프리뷰 placeholder 아웃라인 (PageStructurePreview 신설)
  - 페이지 JSON 트리를 그대로 와이어프레임으로 그리는 컴포넌트를 새로 만들었다. Heading/Text는 선, 그 외는 테두리 있는 블록으로 환원한다.
  - 여기서 제일 고민한 건 높이 배분이었다. 실제 캔버스 높이 비율을 그대로 쓰면 큰 본문이 헤더·통계 영역을 완전히 밀어내서 썸네일이 "덩어리 하나"로 보인다. 그래서 제곱근으로 압축한 가중치를 썼다. 상대적 크기 관계는 남기되 각 구획이 식별 가능한 최소 크기를 갖게 하는 절충이다.

- 컴팩트 폼 프리뷰 확장
  - 폼 계열 프리셋처럼 요소가 작고 촘촘한 경우 프리뷰가 뭉개져서, 해당 케이스만 별도로 넓혀 잡았다.

- 모든 프리셋 프리뷰 감사 (E2E)
  - 프리셋 목록을 하드코딩하지 않고 순회하며 프리뷰를 검증하는 스펙을 붙였다. 프리셋이 늘어나도 테스트가 따라오게 하려는 의도다.

- 프리뷰 테두리 가시성 단언
- 폼 프리뷰 기하 검증
- 렌더된 테두리 알파 측정
  - 위 세 개는 같은 흐름이다. "테두리 클래스가 붙어 있다"만으로는 실제로 보이는지 알 수 없어서, 렌더 결과의 실측 geometry와 계산된 알파값까지 확인하도록 단계적으로 조였다. 스타일 회귀는 클래스 존재 단언으로는 절대 안 잡힌다는 걸 다시 확인했다.

- 페이지 프롬프트 빌더 추가
  - 이날의 핵심 축이 여기서 시작됐다. 목업을 실제 앱 코드로 옮기는 핸드오프 프롬프트를 생성하는 모듈을 만들었다.
  - 원본 JSON을 프롬프트에 통째로 끼워 넣지 않고 저장소 상대 경로만 주는 방식을 택했다. 프롬프트가 최신 파일을 직접 읽게 해서 스냅샷이 낡는 문제를 없앤다.
  - apply(신규 구현)와 ejected modify(이미 승격된 코드 수정) 두 종류로 나눴다. 후자는 `Ejected from page mockup: <slug>` 프로비넌스 주석을 계보 검색어로 쓴다.

- 테마 대응 상세 캔버스 복원
  - 상세 라우트가 `bg-white` 고정이라 다크 테마에서 깨졌다. 라우트 정의의 `bareBackground` 플래그를 `detailCanvas`로 바꾸고, 라이트는 흰색·다크는 브랜드 그라디언트를 쓰는 전용 캔버스 클래스로 교체했다. 불리언 이름이 "무엇을 끄는가"가 아니라 "무엇을 적용하는가"를 가리키게 바꾼 게 실질적인 개선이었다.

- 테마 상세 배경 커버리지 추가

- 페이지 크기 hover 잔광 제거
  - `.ph-pagesize-opt`의 transition에 `background`가 물려 있어서 커서가 지나간 뒤에도 배경이 서서히 남았다. border-color만 전이하도록 줄였다.

- 페이지 크기 hover 상태 커버리지 추가

- 삽입 최근 항목 통합
  - 퀵 인서터와 컨텍스트 메뉴가 각자 "최근 삽입" 상태를 들고 있던 걸 `insert-recents` 모듈 하나로 합쳤다. 컴포넌트와 템플릿을 `{kind, key}` 형태로 동일하게 다루고, localStorage 접근은 전부 try/catch로 감쌌다. 프라이버시 모드에서 스토리지가 막혀도 삽입 자체는 되어야 한다는 판단이다. 변경은 CustomEvent로 브로드캐스트해 여러 UI가 같은 목록을 본다.

- 컴팩트 최근 삽입 메뉴 추가
  - 노드 컨텍스트 메뉴 안에 최근 삽입 목록을 얹었다.

- 퀵 인서터의 템플릿 저장 제거
  - 위 작업과 짝이다. 템플릿 저장 진입점을 두 곳에 두지 않기로 하고 퀵 인서터 쪽을 통째로 걷어냈다. 코드와 전용 CSS까지 200줄 넘게 삭제됐다.

- 노드 컨텍스트에서 템플릿 저장
  - 대신 컨텍스트 메뉴로 옮겼다. 현재 선택을 분리된 JSON으로 캡처하는 `selection-snapshot`을 만들었는데, 규칙이 세 가지다. 단일 선택은 그대로, 여러 형제는 문서 순서를 유지한 채 Stack으로 감싸기, 이미 선택된 노드의 자손은 제외.

- 컨텍스트 삽입·템플릿 저장 커버리지 추가

- 선택 스냅샷 타입 정리
  - 위 모듈에서 `eslint-disable @typescript-eslint/no-explicit-any`를 걷어냈다. Puck API 표면을 필요한 만큼만 인터페이스로 좁히고, 노드 판별은 타입 가드로 처리했다. any를 지우는 게 목적이 아니라, 어떤 값이 들어올 수 있는지를 명시하는 게 목적이었다.

- 최근 항목 root-tail 선택 단언

- 캔버스 도크 full-pill 처리
  - 캔버스에 떠 있는 세 개의 도크(도구 바·줌 바·이름표)가 16px 라운딩이라 높이에 따라 양 끝 모양이 제각각이었다. 기존 `--ph-radius-pill`(16px)은 undo 토스트용으로 남기고, `--ph-canvas-dock-radius-full`(999px)을 새로 정의해 도크만 쓰게 했다. 리터럴 대신 named token을 쓰는 건 chrome:lint 규칙 때문이기도 하다.

- 잘리지 않는 도크 포커스 표면 보존 (문서화)
- full-pill 캔버스 도크 검증

- 커스텀 필드의 암묵적 활성화 중단
  - 인스펙터의 커스텀 필드들이 `FieldLabel` 기본 요소인 `<label>`로 감싸여 있었다. 세그먼트 컨트롤이나 스와치 그룹처럼 내부에 여러 컨트롤이 있는 경우, 라벨을 클릭하면 의도치 않게 첫 번째 컨트롤이 활성화된다. `el="div"`로 바꾸고, 대신 스와치 그룹에는 `role="radiogroup"`에 `aria-label`을 붙여 접근성 이름을 유지했다. 라벨-컨트롤 연결을 끊는 대신 이름을 다른 경로로 준 것이다.

- update (갤러리 전반 갱신)
  - 하루 중 제일 큰 커밋이다. 프롬프트 복사 버튼, 히스토리 패널 개편, 인덱스 라우트 재구성, 페이지 배경 토큰 처리, vite 플러그인과 page 스크립트 확장, AGENTS.md와 awl 설정이 한 번에 들어갔다.
  - `PromptCopyButton`은 카드 전체가 stretched-link인 표면 위에 놓이기 때문에 클릭 시 `preventDefault`/`stopPropagation`으로 복사만 실행하게 했다. 상태는 idle/done/failed 세 가지로 두고 1.6초 후 되돌린다.
  - `page-background`는 저장된 페이지 배경 토큰을 정적 Tailwind 클래스로 매핑한다. 런타임 문자열 조합으로는 Tailwind가 클래스를 뽑아내지 못하기 때문에 명시적 레코드가 필요하다. RootRender와 같은 규칙을 공유해야 미리보기와 실제 렌더가 어긋나지 않는다.

- error 복원
  - 위 커밋에서 App.tsx의 `detailCanvas` 적용이 되돌아가 있던 걸 복구했다. 큰 커밋에 여러 갈래를 몰아 넣으면 이런 게 섞여 들어온다.

- 커스텀 필드 활성화 커버리지 마감

- 활동 히스토리 프롬프트 노트 단순화
  - 히스토리 타임라인의 노트가 말풍선(테두리+배경+둥근 모서리)으로 렌더되고 있었는데, 프롬프트 노트는 채팅이 아니라 메타데이터다. 테두리와 배경을 벗기고 muted 텍스트로 낮췄다.

- 긴 히스토리 노트 줄바꿈 커버리지
- 활동 히스토리 타임라인 셸 보존
- 히스토리 노트 테마·격리 검증
- 임시 E2E 페이지 아티팩트 제거
  - 위 네 개는 히스토리 패널 스타일 회귀를 막는 세트다. 검증용으로 커밋했던 픽스처 JSON은 테스트가 자체 생성하도록 바꾸고 다시 지웠다. 저장소에 테스트 부산물을 남기지 않는 쪽이 맞다.

- 새 페이지 프리셋 매트릭스를 레지스트리에서 파생
  - 프리셋 기하 검증 테스트가 프리셋 목록을 하드코딩하지 않고 레지스트리 소스에서 끌어오게 했다. 프리셋을 추가했는데 테스트가 조용히 지나가는 상황을 막는다.

- 새 페이지 프리셋 전반의 placeholder 기하 수정
  - 두 갈래 문제였다. 하나는 화면 맞춤 줌이 수동 줌 하한(25%)에 걸려 긴 페이지 전체가 안 보이는 것. 수동 하한과 fit 하한을 분리하고, 반올림 대신 내림으로 바꿔 1px 잘림도 없앴다. 슬라이더 min은 현재 줌과 하한 중 작은 값으로 둬서 표시값이 거짓말하지 않게 했다.
  - 다른 하나는 Row 안의 hug Placeholder가 padding 폭까지 쪼그라드는 것. absolute로 배치된 태그가 intrinsic width에 기여하지 않아서 생기는 문제라, 명시적 hug인 경우에만 최소 폭을 부여했다. authored fixed 폭은 그대로 존중한다.

- 세로 placeholder 발자국 포함 검사
- 프리셋 JSON 들여쓰기 정규화

- 즉시 eject 스냅샷을 로드된 소스에서 초기화
  - eject 라이프사이클 작업의 시작. 편집 화면 진입 직후 eject를 누르면 스냅샷이 비어 있는 문제를 로드된 소스 기준으로 초기화해 해결했다.

- ejected 프롬프트 라이프사이클을 유한하고 복구 가능하게
  - 여기가 이날 제일 큰 설계 변경이다. 기존엔 메타데이터가 불완전해도 `??` 폴백으로 그럴듯한 프롬프트를 만들어 냈다. 잘못된 slug나 버전을 가리키는 프롬프트가 복사되고, 그게 히스토리에도 기록됐다.
  - slug/버전 정규식 검증을 앞에 세우고 `prepareEjectedModifyPrompt`가 `{ok, prompt} | {ok:false, error}`를 돌려주도록 바꿨다. 클립보드나 히스토리 같은 부작용 이전에 실패를 확정하는 경계다.
  - 히스토리 기록 API도 갈랐다. 결과를 사용자에게 보여줘야 하는 경로는 `appendHistory`로 실패를 던지고, 진짜 best-effort인 경로만 기존 `logHistory`가 삼킨다. "실패를 무시한다"는 결정이 호출부마다 명시되게 하려는 의도였다.

- 프롬프트 라이프사이클 작업 취소
  - 클립보드 API는 AbortSignal을 받지 않는다. 그래서 취소가 불가능하다고 넘어가기 쉬운데, 호출자 입장에서 필요한 건 "플랫폼 호출을 실제로 중단하는 것"이 아니라 "기다림을 끝내고 뒤늦은 결과를 무시하는 것"이다.
  - `startCancellableTask`를 만들어 그 계약만 제공했다. 타임아웃 데드라인, signal 인지 작업의 abort, 대기 브랜치의 reject, 그리고 이미 settled면 이후 플랫폼 응답을 버리는 것까지. signal을 못 받는 API도 감쌀 수 있다.

- eject 라이프사이클 커버리지 확장

- 차트 첫 측정 안정화
  - recharts `ResponsiveContainer`가 ResizeObserver 루프 경고의 발원지였다. 컨테이너가 크기를 관측하고, 그 결과로 SVG를 렌더하고, 그 렌더가 다시 관측 사이클에 동기적으로 재진입한다.
  - `ResponsiveContainer`를 걷어내고 호스트 div를 직접 측정하는 훅으로 바꿨다. 핵심은 observer 콜백에서 곧바로 setState 하지 않고 `requestAnimationFrame`으로 한 프레임 미루는 것. 새 SVG 렌더가 관측 전달 사이클 안에서 일어나지 않게 된다. 측정 전에는 차트를 아예 마운트하지 않고, 같은 크기면 상태 갱신을 건너뛴다.

- 편집기 저장을 복구 가능하게
  - 저장 실패나 예기치 않은 이탈로 작업이 날아가는 문제. localStorage 기반 복구 초안 계층을 만들었다.
  - 키는 `slug:baseVersion`으로 잡아 다른 버전 기반의 초안이 섞이지 않게 했고, 초안에 FNV-1a 해시를 같이 저장해 읽을 때 데이터 무결성을 검증한다. 해시가 안 맞으면 유효한 초안으로 인정하지 않는다.
  - 스토리지 실패는 조용히 넘기지 않고 어떤 동작(저장/읽기/삭제)에서 무슨 예외가 났는지 한국어 메시지로 돌려준다. 용량 초과와 접근 차단은 사용자가 대응할 수 있는 정보다.

- 복구 시 저장된 제목 보존
  - 복구 초안을 되살릴 때 제목이 초기값으로 되돌아가던 회귀를 잡았다.

- 편집기 ResizeObserver 추적·정리
  - 차트 쪽을 고쳤어도 편집기 전체에 남은 ResizeObserver 누수·루프가 더 있는지 확인해야 했다. 관측자 생성·observe·unobserve·disconnect·전달 시작/종료를 전부 계측하는 Playwright 진단 유틸을 만들었다. 런타임 경고가 뜨면 직전 전달 시퀀스를 기준으로 후보 관측자를 지목한다.
  - 경고 문자열만 잡는 테스트는 "어디서 났는지"를 알려주지 않아서 결국 추적 불가능한 플레이크가 된다. 원인을 지목할 수 있는 형태로 만들어 둔 게 이 작업의 목적이었다.

## 정리

이날 커밋 대부분은 결국 하나의 질문으로 수렴한다. **"실패하거나 중단될 수 있는 일을, 어디서 어떻게 끝낼 것인가."**

오전의 프리뷰 작업은 그 질문이 시각적으로 나타난 형태였다. 제곱근 압축이든 fit 하한 분리든, 결국 "화면에 안 들어가는 상황을 어디서 처리할 것인가"의 문제다. 그리고 그걸 검증하려면 클래스 존재 단언으로는 부족해서 실측 geometry와 알파값까지 재야 했다. 스타일 회귀는 스타일 코드가 아니라 렌더 결과에서만 보인다.

오후의 통합 작업은 진입점을 줄이는 쪽이었다. 최근 삽입도, 템플릿 저장도 두 군데에 있으면 두 군데가 서서히 어긋난다. 한 곳으로 모으면서 코드가 200줄 넘게 줄었는데, 줄어든 게 이득이라기보다 "어긋날 자리가 없어진" 게 이득이다. 커스텀 필드의 암묵적 활성화도 비슷한 결이다. `<label>`이 주는 편의(클릭하면 컨트롤이 활성화)가 다중 컨트롤에서는 버그가 되므로, 편의를 버리고 접근성 이름을 별도 경로로 준다.

저녁의 라이프사이클 작업이 제일 많이 남았다. 세 가지가 같은 교훈을 다른 각도에서 줬다.

`prepareEjectedModifyPrompt`는 **폴백이 항상 친절한 건 아니라는 것**을 알려줬다. `page.derivedFrom?.slug ?? page.slug`는 코드를 안 터지게 만들지만, 대신 틀린 경로를 가리키는 프롬프트를 만들어 낸다. 사용자는 그게 틀렸다는 걸 붙여넣기 한참 뒤에나 안다. 부작용 앞에 검증 경계를 세우는 편이 훨씬 정직하다. 히스토리 API를 strict와 best-effort로 나눈 것도 같은 이유다. 실패를 삼키는 건 결정이지 기본값이 아니다.

`startCancellableTask`는 **취소의 계약을 다시 정의하는 문제**였다. 클립보드가 AbortSignal을 안 받으니 취소를 못 한다고 생각하기 쉬운데, 호출자가 원하는 건 플랫폼 호출의 중단이 아니라 자기 대기의 종료다. 그 둘을 분리해서 보면, signal을 못 받는 API도 충분히 유한한 라이프사이클로 감쌀 수 있다.

`ResponsiveContainer` 제거는 **편의 래퍼가 감추고 있던 비용**이었다. 관측 → 렌더 → 재관측이 한 사이클 안에서 도는 구조는 라이브러리 안에 숨어 있어서 밖에서는 원인을 짚을 수 없다. rAF로 한 프레임 미루는 한 줄이 해법이었지만, 거기 도달하기까지가 오래 걸렸다. 그래서 마지막 커밋으로 ResizeObserver 계측 유틸을 만들어 둔 것이다. 다음에 같은 경고를 만나면 "어디서"부터 시작할 수 있게.

저장 복구에서 해시를 같이 저장한 것도 붙여 둘 만하다. localStorage는 다른 탭, 이전 버전, 부분 실패로 얼마든지 오염된다. 읽을 때 무결성을 확인하지 않으면 복구가 오히려 손상을 되살린다. 복구 기능은 "저장했느냐"가 아니라 "되살린 게 맞느냐"까지가 범위다.
