# Puck을 접고, 리뷰와 시연을 갤러리 안에서 다시 세운 날

> UX 마찰로 실사용률이 낮던 Puck 손 조립 편집기에 투자를 멈추고, 리스트와 상세 리뷰 화면을 컴포넌트 갤러리 안에 새로 지었다. 포인팅만 허용하는 피드백과 그대로 붙여넣어 실행 가능한 프롬프트로 저작 루프를 닫았고, 미리보기를 구조 스케치에서 실 컴포넌트 렌더로 끌어올렸다. 오후에는 페이지를 이어 붙여 백엔드 없이 화면 전환만으로 시연하는 프로토타입 흐름과 xyflow 지도를 만들었다.

## 배경

page-harness는 Puck 기반의 손 조립 편집기였다. 드래그로 컴포넌트를 놓고 props를 만지는 방식인데, 실제로는 잘 쓰이지 않았다. 조립 자체가 마찰이 크고, 그럴 바에는 `/page-create` 스킬에 설명을 주고 AI가 초안을 조립하게 하는 편이 빨랐다. 그래서 아침에 방향을 뒤집었다. 편집기는 동결하고, 사람이 실제로 하는 일(만들어진 페이지를 보고 고칠 곳을 짚어 주는 일)만 남겨 컴포넌트 갤러리 안에 새로 만들기로 했다.

이 결정에는 조건이 하나 붙었다. 새 화면은 page-harness의 어떤 소스도 import하지 않는다. 나중에 page-harness를 통째로 지워도 깨지지 않아야 하기 때문이다. 그래서 `pages/*.json`을 자체 리더로 직접 읽고, 파일락 규약만 맞춰 안전하게 공유하는 구조를 택했다. 하루의 절반은 그 자립 조건 아래서 리뷰 표면을 실용 수준까지 끌어올리는 일이었고, 나머지 절반은 그렇게 만든 페이지를 이어 붙여 "실제 서비스처럼 넘어가는" 시연을 만드는 일이었다.

## 핵심 내용

### 개별 작업 기록 (시간순)

- 컴포넌트 복원 기능 실검증 (자정 무렵)
  - 전날 만든 복원 경로를 `restore-test` 컴포넌트로 실제로 두드렸다. 라벨과 색을 v3로 바꾸고, 그 상태에서 이전 두 시점으로 각각 되돌려 봤다. 복원할 때마다 `restore-test.history.jsonl`에 modified와 restored 이벤트가 쌓이는 것까지 확인했다.

- Puck 편집기 동결, 페이지 플레이그라운드를 컴포넌트 갤러리로 이관
  - page-harness에 추가 투자를 중단했다. `ui:harness` 통합 런처와 컴포넌트 갤러리 헤더의 상호 연동 버튼을 제거하고, `/page-create` 스킬은 설명만으로 AI가 초안을 조립하는 경로를 기본으로 승격했다.
  - 리스트와 상세 리뷰 화면을 `@maxflow/ui-harness` 안에 "페이지 플레이그라운드"로 새로 만들었다. page-harness를 나중에 통째로 지워도 깨지지 않도록 어떤 소스도 import하지 않고 `pages/*.json`을 자체 리더(`lib/pages-store.ts`)로 직접 읽는다. 미리보기는 라이브 Puck 렌더 대신 타입과 레이아웃만의 구조 스케치(`PageStructureSketch`)로 그렸다.

- 포인팅 피드백과 일괄 프롬프트 복사 추가
  - 구조 스케치 위 요소(또는 전체 레이아웃)를 클릭해 코멘트를 남긴다. 드래그나 리사이즈 같은 조작 기능은 넣지 않았다. 포인팅만 허용하는 것이 Puck 재발 방지 가드레일이다.
  - 피드백은 `pages/<slug>.feedback.json`에 저장한다. page-harness를 참조하지 않고 락 파일명 규약만 맞춘 자체 구현이다.
  - 남긴 코멘트를 모두 모아 대상 컴포넌트의 최초 생성 프롬프트까지 붙여 정형 텍스트로 일괄 복사한다. CC CLI에 바로 붙여넣는 용도다. 실브라우저로 포인팅부터 코멘트 저장, 전체 레이아웃 피드백, 삭제까지 실제 API와 파일 반영을 확인했다.

- 페이지 in-place 복원 구현 (AC-04 4조건)
  - page-harness `PageVersionsPanel.tsx`의 AC-04 주석이 명시했던 네 조건(diff 리뷰, 정확한 확인문, 복구 전 스냅샷, 낙관적 baseVersion)을 플레이그라운드에 구현했다.
  - page-harness는 여전히 "새 draft로 복구"만 지원한다(원본 불변 우선). 이쪽은 같은 페이지를 제자리에서 되돌리는 것이 목적이라 별도 구현이 맞다고 판단했다. import 없이 자체 소유(`pages-write.ts`/`pages-restore-store.ts`)하고 파일락 규약만 맞춰 공유한다. 실제 페이지로 diff 확인, 낙관적 락 충돌(409), 복원, 재복원까지 실브라우저와 API로 검증했다.

- page-create SKILL.md 트리거 설명을 GUIDE.md 재편과 일치시킴
  - description이 여전히 "포트 9222", "사람이 Puck으로 초안, AI가 refine"으로 남아 있어 아침에 뒤바꾼 기본/보조 경로와 어긋나 있었다. 스킬 발견 텍스트도 "설명만으로 AI가 조립"이 기본이 되도록 맞췄다.

- 페이지 리뷰 UX 개선: 노드 팝오버 작성, 컴포넌트 지목, 실행 가능한 일괄 프롬프트
  - 목록을 컴포넌트 라이브러리(`LibraryRoute`)와 같은 리듬으로 재설계했다(히어로, 검색, 툴바, 카드 그리드). 카드는 `ComponentCard` 프레임을 그대로 따르고 구조 스케치를 썸네일로, 피드백 건수를 뱃지로 얹는다.
  - 상세는 하단 폼으로 시선을 옮기던 방식을 걷어내고, 요소를 클릭하면 그 자리에 팝오버가 열려 바로 작성하게 했다. 뷰포트를 넘기는 위치면 실측해 안쪽으로 보정한다. 리프 노드의 truncate가 팝오버를 잘라서 라벨 span으로 옮겼다.
  - 피드백에 "이 자리에 배치할 컴포넌트"를 지목할 수 있게 했다. 배치 자체는 하지 않는다. 지목만 남기고 조립은 프롬프트를 받은 `/page-create`가 수행한다. 포인팅 전용 가드레일을 유지하는 방식이다.
  - 일괄 복사가 코멘트만 나열해 받는 쪽이 실행할 수 없었다. 대상 페이지 식별(파일 경로, 현재 버전), 동시성 안전 저장 절차, 구조 덤프, 노드 트리 경로, 지목 컴포넌트의 import와 최초 생성 프롬프트까지 실어 그대로 붙여넣어 실행 가능한 프롬프트로 만들었다.

- 리뷰 표면 공용 컴포넌트 3종 추가 + 전체화면 리뷰로 재구성
  - 레퍼런스 디자인에 맞춰 재사용 가능한 조각을 `packages/ui`로 올리고 플레이그라운드가 그걸 조합해 쓰도록 바꿨다. 갤러리 전용 일회성 UI를 만들지 않는다는 원칙이다.
  - `feedback-composer`는 채팅 입력창 형태의 작성기다. 제출은 우하단 원형 버튼 하나로 고정하되 화살표가 아니라 +를 썼다. 이 표면의 동작은 "보내기"가 아니라 "항목을 하나 더 쌓기"이기 때문이다.
  - `action-menu`는 아이콘과 제목/설명, 단축키 힌트 행과 하단 안내 줄을 갖춘 커맨드 팔레트형 메뉴다.
  - `comment-timeline`은 코멘트 흐름이다. 액션을 항목 아래 버튼 줄이 아니라 우상단 슬롯에 모았다. 목록이 길어질수록 아래 버튼 줄이 항목 경계를 흐리기 때문이다. 수정은 화면 이동 없이 인라인으로 한다.
  - 상세를 전체화면 팝업으로 바꿨다. 리뷰는 목록과 오가는 작업이라 배경을 남긴 채 겹치는 편이 맥락을 덜 잃는다. main 안(`anim-fade-in`)에 두면 그 래퍼의 스태킹 컨텍스트에 z-50이 갇혀 sticky 헤더 아래로 깔리므로 다른 오버레이와 같은 층에 뒀다.
  - 미리보기에 최소/요약/라이브 토글을 넣고, 피드백 인라인 수정을 위해 `PATCH /api/pages/<slug>/feedback/<id>`를 추가했다(본문만 고친다).

- 요약/라이브에서 페이지를 실제 모습으로 렌더 + 포인팅 상호작용 정리
  - 요약과 라이브가 레지스트리 컴포넌트만 그리고 Heading/Text/Placeholder 같은 레이아웃 프리미티브는 이름 박스로 남아, 프리미티브 위주 페이지에선 최소 모드와 차이가 없었다. 원인은 서버가 `previewContent`에서 props를 전부 버려 그릴 재료가 없었던 것이다.
  - 렌더에 필요한 prop만 화이트리스트로 실어 보낸다(text·level·muted·label·height·gap·align·justify·wrap·padding). 임의 prop을 통째로 흘리지 않아 업무 데이터는 딸려가지 않는다. 상세는 목록 썸네일용 얕은 상한(깊이 4, 16개) 대신 넉넉한 상한(깊이 10, 64개)을 쓴다.
  - Stack/Row/Grid/Frame을 점선 상자가 아니라 진짜 flex와 grid로, 프리미티브를 실제 제목/본문/자리표시로 방출하게 했다(`PageStructureSketch.live`). page-harness 렌더러 없이 ui-harness 자체 구현이다.
  - 포인팅 쪽은 팝오버를 노드 좌측이 아니라 중앙 하단에 붙이고, 열릴 때 본문에 커서를 뒀다. 바깥 클릭 해제를 pointerdown capture에서 걷어낸 게 핵심이다. 다른 노드를 누르면 닫기, 선택, 다시 열기가 되어 팝오버가 튀었다. 이제 미리보기 영역이 버블링으로 받아 처리하고 선택 전환은 팝오버가 열린 채로 이동한다. 닫기 버튼은 헤더 줄 안에서 배경에 묻혀 안 보이길래 카드 모서리에 흰 배경과 테두리로 띄웠다. 목록 검색은 컴포넌트 라이브러리처럼 앱 헤더 가운데 슬롯으로 포털했다.

- 미리보기가 페이지에 지정된 props로 실 컴포넌트를 그리게
  - 레지스트리 컴포넌트를 늘 데모로 그려서, `/page-create`가 프롬프트를 받아 props를 고쳐 넣어도 리뷰어가 그 결과를 볼 수 없었다. 고친 걸 확인할 수 없으니 리뷰 루프가 닫히지 않는다. 재료는 이미 다 있었는데(실 컴포넌트 `staged[key]` + 엔트리 `meta.props` 스키마) 서버가 props를 화이트리스트로 버리고 있던 게 원인이었다.
  - 상세 응답은 노드의 모든 prop을 싣는다(fullProps). 목록 썸네일은 기존 화이트리스트를 유지했다. 상세는 어차피 data 원문을 함께 싣고 있어 새로 노출되는 정보가 없다.
  - 엔트리에 prop 스키마가 있고 노드가 props를 들고 있으면 데모 대신 실 컴포넌트에 그대로 넘긴다(page-create GUIDE 10절과 같은 계약). `_role`·`_width` 같은 편집 신호는 실 컴포넌트가 모르는 prop이라 걸러낸다. 렌더 실패는 `SafePreview`가 잡아 페이지 전체가 죽지 않는다.
  - 미리보기 트리를 `pages-preview.ts`로 분리했다(300줄 정책). 공개 표면은 re-export로 유지했다. 검증은 `situational-alert`에 title·description·confirmLabel·cancelLabel을 넣고 라이브 모드에서 네 값이 모두 실제로 렌더되는 것으로 했다.

- 케밥 메뉴 z-레이어, 팝오버 격리, 리뷰 화면 표면 정리
  - 케밥 메뉴가 열려도 안 보여서 무반응처럼 느껴졌다. `@maxflow/ui` Popover는 Positioner에 `z-popover`(35)를 붙이는데, 갤러리는 자기 모달 셸(Dialog, z-50)을 직접 만들어 라이브러리의 모달 레이어 선언을 타지 않는다. 늘 35로 떨어져 패널 뒤에 깔렸다. `@utility` 재정의는 원본에 밀리므로 레이어 밖 규칙으로 덮었다.
  - 팝오버를 포털로 뺐다. 노드의 자식으로 두면 라이브 모드의 형제 데모가 만든 스태킹 컨텍스트나 오버레이에 덮여 클릭이 뒤 노드로 새고, 이벤트도 스케치 트리와 얽힌다. 포털이면 둘 다 사라진다. 앵커는 콜백 ref와 state로 받는다. 객체 ref는 첫 렌더에 null이고 채워져도 리렌더가 없기 때문이다.
  - 신규 3종의 미리보기가 비어 있던 것도 잡았다. 갤러리 demos는 `lazy()`로 로드해 default export를 요구하는데 named export만 있었다(component-create 규약 누락).
  - 작성기는 닫기 버튼을 제거하고(바깥 클릭과 Escape로 닫힘), 대상은 지울 수 없는 회색 태그로 칩 줄에 편입했다. 컴포넌트 지목은 테두리 없는 아이콘 버튼과 툴팁으로 바꿨다. 표면은 미리보기 캔버스 #fff, 헤더와 피드백 패널 #f7f7f7(다크 대응 토큰), 두 스크롤 영역에 `custom-scrollbar`를 적용했다.

- 프리뷰 부재 이유를 화면에 밝히고, 페이지 검색창을 라이브러리와 동형으로

  - ⌘/Ctrl+Enter로 제출되는데 화면 어디에도 그 사실이 없어 발견할 방법이 없었다. 우하단 제출 버튼에 툴팁을 붙이되 표기를 실행 중인 OS로 정했다. macOS는 ⌘, 그 외는 Ctrl이 관례라 한쪽으로 고정하면 다른 쪽 사용자에게 없는 키를 안내하게 된다. 서버 렌더는 Ctrl로 두고 클라이언트에서 정정한다. `aria-label`과 `aria-keyshortcuts`에도 같은 값을 실어 스크린리더에도 동일하게 전달한다.

- slug에 한글 보존
  - 바로 앞 커밋에서 드러난 문제를 근원에서 고쳤다. slugify가 비ASCII를 전부 버려서 "대시보드 초안" 같은 한글 제목은 예외 없이 `page-1785301489300` 같은 slug가 됐다. URL이 의미를 잃고, 목록에서 slug 검색도 안 되며, 앞선 .gitignore 규칙과 겹치면 한글 페이지가 조용히 커밋에서 빠지기까지 했다.
  - slugify가 한글 음절(가-힣)을 보존하게 하고, 실제 글자가 하나도 안 남을 때만(기호만 있는 제목) 타임스탬프로 폴백한다. 기존 영문 slug 결과는 그대로다. `SLUG_RE`는 CLI/스토어와 갤러리 리더 양쪽에 같은 규칙으로 한글을 허용했다. `.`·`/`·`\`는 여전히 문자 집합 밖이라 경로 traversal은 구조적으로 불가능하다.
  - NFC 정규화도 넣었다. macOS는 한글 파일명을 NFD로 저장하는데 URL과 입력은 NFC라 그대로 비교하면 어긋난다. slug를 받는 모든 입구(경로 생성, 디렉터리 읽기)에서 NFC로 모았다. `create "한글 슬러그 검증"`으로 slug `한글-슬러그-검증`을 만들어 목록·상세·피드백 POST/GET 전 구간을 확인했다.

  - `PageFrame`으로 FHD 1920x1080과 QHD 2560x1440 고정 캔버스를 만들고 1:1 + 스크롤로 그린다. 축소하면 `@maxflow/ui` 포털 37개 파일이 `document.body`로 나가 스케일 밖에 그려져 크기와 위치가 어긋나기 때문에, scale<1은 재생 모드 전용으로 남겼다.
  - `page-frame.ts`에 프리셋과 `resolveFrame`(흐름 > 페이지 > FHD), `_width` 파서를 뒀다. 실측상 "264px"·"1/4"·"23%" 세 형태가 공존해 셋 다 흡수한다. `sizing.ts`는 `_widthMode`/`_width`/`_height`/`_alignSelf`/`_padding`을 CSS로 바꾸는데, 부모 방향을 알아야 한다. fill은 Row에서 flex:1, 세로 흐름에서 width:100%다. 모르고 flex:1을 내면 Stack 안에서 세로로 늘어난다.
  - `SketchNode` 반환 분기 4개 전부에 병합했다. 한 군데만 넣으면 조용히 절반만 적용된다. 프레임 토글은 저장하지 않는다. SSOT는 `root.props.pageSize`다. sizing 병합 후 305줄이 되어 300줄 정책을 넘겨 popover를 분리했다. 검증은 FHD에서 QHD로 전환할 때 SNB가 264px를 유지하고 컨텐츠가 1541에서 2181로(+640) 늘어나는 것으로 했다.

- 프로토타입 흐름: flows 저장소, 배선, 재생
  - 페이지를 이어 붙여 실제 서비스처럼 넘어가는 시연을 만들었다. 백엔드 없이 화면 전환만 한다(Figma 프레젠테이션 모드와 같은 개념).
  - 흐름을 페이지 본문(`_goto` 같은 노드 prop)이 아니라 `flows/<slug>.json` 1급 개체로 둔 이유가 있다. 같은 페이지가 여러 시연에 재사용되고, `pages/*.json`은 `/page-create` 스킬과 공유하는 계약이며, 페이지를 옛 버전으로 복원할 때 시연 배선까지 되돌아가면 안 되기 때문이다.

  - 라우트는 `/flows`, `/flows/<f>`, `/flows/<f>/<s>`(배선), `/flows/<f>/play/<s>`(재생)로 뒀다. 재생은 크롬 없이 전체를 차지한다(App에서 훅 이후 early return). 배선은 리뷰의 피드백 팝오버와 같은 자리에 목적지 선택기를 띄운다. `/pages/*`는 손대지 않아 리뷰의 클릭 의미는 "피드백" 하나로 유지된다.
  - `PageStructureSketch`에 hotspotIds와 hotspotFlash를 추가했다. 재생에선 배선된 노드만 눌리고 평소엔 아무 표시도 없다. `useFitScale`은 재생 전용 축소로 하한을 25%로 뒀다(그 아래는 못 읽으니 스크롤에 맡긴다). 화면을 빼도 간선은 지우지 않고 끊김으로 표시한다. 다시 넣으면 되살아난다.
  - 브라우저 실측으로 흐름 생성, 화면 3장 편입(.versions 3개 생성), SNB 2곳 배선, A→B, 뒤로, A→C 분기 이동을 확인했다. 도착 화면 제거 시 "눌러볼 곳 2→1"과 그 핫스팟 사망, 재편입 시 부활까지 봤다. QHD fit scale(0.865278)이 기대값과 일치했고 한글 흐름 이름이 slug로 보존됐다.

- 흐름 지도(xyflow): 핫스팟 핸들, 드래그 재연결, 끊김 표시, 최신본 갱신
  - `/flows/<f>`를 목록에서 xyflow 지도로 바꿨다. 화면 카드마다 핫스팟 하나당 Handle 하나가 서서 "이 흐름 어디까지 배선됐나"가 한눈에 읽힌다.

  - 드래그 연결은 목적지 변경으로만 쓴다. 핫스팟 신설은 지도에서 하지 않는데, 썸네일에서는 어느 요소가 어느 자리인지 못 고르기 때문이다.
  - 끊긴 간선은 빨간 점선과 "끊김" 라벨, 살아있는 간선은 실선이다. xyflow의 animated는 점선으로 그려져 끊김과 모양이 겹치므로 끄고 점선을 한 가지 뜻으로만 쓴다. 최신본으로 갱신(repinScreen) 버튼은 늙은 화면에만 뜬다. `flow-map-layout`은 시작 화면에서 BFS로 열을 배치하는데, 끊긴 간선으로는 깊이가 전파되지 않고 미도달 화면도 반드시 배치한다.
  - 함정 하나를 고쳤다. `FlowDetailRoute`가 `onPatch`를 인라인 화살표로 넘기면 매 렌더 새 함수가 되어 지도의 nodes useMemo가 매번 재계산되고, xyflow가 노드 측정을 끝내지 못해 간선이 통째로 조용히 사라진다. 노드는 보이고 경고도 없다. `useCallback`으로 신원을 고정해 해결했다.
  - 검증은 실제 마우스 드래그로 했다. 핸들이 8px이라 확대 후 15px에서 성공했는데, 합성 PointerEvent는 `setPointerCapture`에서 막힌다. 늙은 흐름(v1.0.0 고정, 최신 v1.0.2)에서 갱신 버튼 노출과 repin 후 스냅샷·미리보기 복구도 확인했다.

- 플레이그라운드 배율·배경 조절, 툴바 세그먼트화, 전체 피드백 앵커 팝오버
  - 미리보기 배율은 고정 스텝(25~150%)으로만 움직인다. 휠 줌의 임의 배율(37.4%)은 "몇 %에서 봤는지"를 재현할 수 없게 해 리뷰 대화가 성립하지 않는다. 축소는 transform scale로 한다(리플로우 없음). CSS zoom은 폰트를 실제로 줄여 문단이 다시 흘러서, 리뷰가 보는 레이아웃이 실제 해상도의 레이아웃과 달라진다. 축소 시 바깥 자리는 ResizeObserver 실측으로 잡는다. frame.h 고정이면 내용이 프레임보다 긴 페이지(대부분)에서 아래가 잘렸다.

  - 툴바는 네 축(프레임·배율·배경·모드)을 button-group 세그먼트로 통일했다. 붙어 있다는 사실이 "같은 축의 선택지"라는 신호라 낱개 칩보다 축 경계가 읽힌다.

## 정리

하루의 큰 줄기는 "쓰이지 않는 것을 접고, 실제로 하는 일만 남기기"였다. Puck 편집기는 기능적으로 멀쩡했지만 사람이 쓰지 않았다. 드래그로 조립하는 것보다 `/page-create`에 설명을 주는 게 빨랐기 때문이다. 그래서 편집기를 지우는 대신 동결하고, 사람이 실제로 하는 일만 새로 지었다. 만들어진 페이지를 보고 고칠 곳을 짚어 주는 일이다.

그 결정이 코드 구조로 그대로 내려간 게 오늘 가장 마음에 드는 부분이다. **"나중에 통째로 지워도 깨지지 않아야 한다"를 import 금지로 못 박은 것.** 새 화면은 page-harness 소스를 하나도 가져오지 않고 `pages/*.json`을 자체 리더로 읽는다. 공유하는 건 데이터 형식과 파일락 규약뿐이다. 덕분에 in-place 복원처럼 두 쪽 철학이 다른 기능(page-harness는 원본 불변 우선의 "새 draft로 복구", 이쪽은 제자리 되돌리기)을 억지로 통합하지 않고 각자 구현할 수 있었다. 코드 중복처럼 보이지만, 동결 대상과의 결합을 만드는 것보다 낫다.

가드레일을 명시적으로 세워 둔 것도 유효했다. 리뷰 표면은 포인팅만 허용한다. 드래그도 리사이즈도 없다. "이 자리에 이 컴포넌트" 지목까지는 되지만 배치는 하지 않는다. 이 선을 계속 지키니까 리뷰가 미니 편집기로 부풀어 오르지 않았고, 대신 "지목을 프롬프트로 바꿔 AI에게 넘기는" 경로가 자연스럽게 주 경로가 됐다. 일괄 복사가 코멘트만 나열해선 받는 쪽이 실행할 수 없다는 걸 알아채고 파일 경로·현재 버전·저장 절차·구조 덤프·노드 경로·컴포넌트 import까지 다 실은 것도 같은 맥락이다. 프롬프트는 요약이 아니라 실행 가능한 명세여야 루프가 닫힌다.

리뷰 루프가 실제로 닫히지 않고 있었다는 걸 정오 무렵에야 알아챈 게 오늘의 반성이다. 미리보기가 레지스트리 컴포넌트를 늘 데모로 그리고 있어서, AI가 프롬프트를 받아 props를 고쳐 넣어도 리뷰어는 그 결과를 볼 수 없었다. 재료는 전부 갖춰져 있었는데 서버가 props를 화이트리스트로 버리고 있었다. 오전 내내 "피드백을 남기는 쪽"만 다듬고 "고쳐진 걸 확인하는 쪽"은 안 보고 있었던 셈이다. 루프의 절반만 보면서 완성됐다고 느끼기 쉽다.

스태킹 컨텍스트로 두 번 데인 것도 기록해 둘 만하다. 갤러리가 라이브러리의 모달 셸을 안 쓰고 자기 Dialog를 직접 만드는 바람에, 라이브러리 Popover의 z-popover(35)가 갤러리 모달(z-50) 뒤에 영원히 깔렸다. 팝오버를 노드 자식으로 두니 라이브 모드의 형제 데모가 만든 스태킹 컨텍스트에 덮여 클릭이 뒤로 샜다. 둘 다 포털이 답이었고, 결론은 하나다. **레이어 선언을 라이브러리가 하는데 셸은 앱이 만들면 그 둘은 언젠가 어긋난다.** Escape가 팝오버 대신 화면 전체를 닫던 것도 결이 같다. document 버블이 window 버블보다 먼저라 window에 건 stopPropagation이 구조적으로 항상 늦었다. 이벤트를 어디에 걸었는지가 우선순위를 정한다.

방향을 하루 안에 두 번 뒤집은 것도 있었다. 오후 2시에 feedback.json을 "런타임 잔재"로 보고 추적 해제했다가, 20분 뒤에 되돌렸다. page-harness의 .gitignore를 베끼면서 그 규칙의 전제("혼자 쓰는 편집기")까지 딸려온 게 원인이었다. 플레이그라운드는 팀이 함께 보는 리뷰 표면이라 전제가 정반대다. 설정 파일을 복사할 때는 값이 아니라 그 값이 성립하는 전제를 옮겨야 한다. 로고 배지도 비슷했다. 오후 2시 42분에 Gallery 필기체 배지를 붙였다가 5시 13분에 뗐다. 흐름 화면을 만들고 나니 하네스가 갤러리 하나만 가리키는 도구가 아니게 됐기 때문이다.

그 gitignore 사고가 slug 버그를 끌어낸 건 운이 좋았다. `pages/page-*.json` 무시 규칙을 들여다보다가, slugify가 비ASCII를 버려서 한글 제목 페이지는 전부 `page-<timestamp>`가 된다는 걸 알았다. 두 개가 겹치면 한글로 만든 페이지가 조용히 커밋에서 빠진다. 고치면서 macOS의 NFD 파일명까지 나왔다. 파일명을 사용자 입력에서 파생시키는 순간 정규화 형식은 반드시 한 곳으로 모아야 한다.

오후의 흐름(flows)에서 가장 오래 고민한 건 "배선을 어디에 저장할 것인가"였다. 페이지 노드 prop으로 넣으면 구현이 훨씬 쉽지만 세 가지가 깨진다. 같은 페이지가 여러 시연에 재사용되고, `pages/*.json`은 `/page-create` 스킬과 공유하는 계약이며, 페이지를 옛 버전으로 복원할 때 시연 배선까지 되돌아가면 안 된다. 1급 개체로 뺀 대신 "화면 편입 시 그 순간 본문을 `.versions/`에 write-once로 박제"가 필요해졌는데, 이건 오히려 얻은 것이다. 시연이 가리킬 고정점이 생겨서 페이지가 나중에 바뀌어도 시연은 안 깨지고, 대신 "최신본으로 갱신" 버튼이 늙은 화면에만 뜬다.

xyflow에서 `onPatch`를 인라인 화살표로 넘겼다가 간선이 통째로 사라진 건 오늘 가장 무서웠던 버그다. 매 렌더 새 함수가 되어 nodes useMemo가 재계산되고, xyflow가 노드 측정을 끝내지 못한다. 그런데 노드는 정상적으로 보이고 콘솔 경고도 없다. 참조 동일성이 깨졌을 때 라이브러리가 조용히 절반만 포기하는 종류의 실패라, 증상만으로는 원인에 도달할 방법이 없다. `useCallback`이 성능 최적화가 아니라 정확성 요건인 경우가 있다는 걸 다시 확인했다.

마지막으로 색 문제 두 건은 처방의 층위가 달랐다는 점이 남는다. 갤러리 중립색의 파란끼는 토큰을 chroma 0으로 내려 해결했고, 다크 hover가 안 보이던 건 호출부 56곳을 고치는 대신 `--st-muted`를 0.271에서 0.3으로 올려 해결했다. 둘 다 "호출부가 아니라 토큰을 고친다"인데, 후자는 밝기 델타 0.039가 지각 임계 아래라는 실측이 있어야 정당화된다. 감으로 "좀 더 밝게"가 아니라 숫자로 간격을 벌린 것이 다음에 또 좁아졌을 때 판단 기준으로 남는다.
