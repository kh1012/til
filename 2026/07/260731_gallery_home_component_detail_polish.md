# Figma 픽셀과 레포 스케일이 부딪히는 자리

> Figma의 'MX 새로운 Home'을 컴포넌트로 옮기다 보면 반드시 한 번은 부딪힌다. 시안은 11px ExtraBold라고 말하는데 레포에는 그런 조합이 없다. 픽셀을 그대로 베낄지 스케일을 지킬지 사이에서 세 번 조정했다. 그 사이 테마 토글은 크로스페이드에서 원형 확산으로 바꿨고, 상세 페이지의 사용 예제는 자리를 옮겨 한 행으로 눌렀다.

## 배경

즉시 실행 터미널을 다듬는 사이사이에 갤러리 자체의 표면도 만졌다. 두 갈래였다.

하나는 Figma에서 새로 나온 'MX 새로운 Home' 시안을 컴포넌트로 옮기는 일이다. 레지스트리를 뒤져 70% 이상 겹치는 기존 Composite이 없어서(component-create GUIDE §4 기준) 신규 생성으로 갔다. 인사 헤딩, 첫 프로젝트 그룹 생성을 유도하는 카드, 퀵스타트 추천 작업 목록 세 덩어리다.

다른 하나는 상세 페이지와 헤더의 표현 정리다. 어제부터 상세 페이지를 계속 들여다보고 있는데, 사용 예제가 좌측 칼럼에서 히스토리 옆에 세로로 길게 붙어 있는 게 계속 걸렸다. 테마 토글도 마찬가지로, `@maxflow/ui`에 이미 만들어둔 AnimatedThemeToggler가 정작 갤러리 헤더에서는 안 쓰이고 있었다.

## 핵심 내용

### 개별 작업 기록 (시간순)

- home-getting-started 컴포넌트 생성
  - Figma 'MX 새로운 Home'(node 2:4052) 재현. 인사 헤딩 + 첫 프로젝트 그룹 생성 유도 카드 + 퀵스타트 추천 작업 목록.
  - 레지스트리에 70% 이상 겹치는 기존 Composite이 없다고 판단해 신규 생성했다. component-create GUIDE §4가 이 판단을 요구하는 이유는 명확하다. 겹치는 게 있는데 새로 만들면 라이브러리가 두 배로 늘고 어느 쪽이 정본인지 아무도 모르게 된다.
  - 조각은 group-prompt / quick-start / types로 나누고 데모·스토리·엔트리까지 프로토콜대로 붙였다.

- 인사 헤딩 자간 좁힘
  - 큰 헤딩은 기본 자간이면 넓어 보인다. 한 줄 조정.

- 그룹 생성 버튼 Figma 스펙 정합
  - 높이·패딩·아이콘 크기·글자 굵기·그림자를 Figma 노드 2:4082 기준으로 맞췄다. 여기까지는 시안을 그대로 따라간 단계다.

- 그룹 생성 버튼 크기 조정(151x36 근사)
  - 그런데 시안이 요구한 11px ExtraBold를 그대로 넣으면 레포 어디에도 없는 조합이 생긴다. 이 저장소는 타이포를 step 스케일로 다루고, 임의 px 값을 넣는 순간 그 버튼만 스케일 밖으로 나간다.
  - 그래서 레포 표준 스케일(`text-step-n2` + `font-semibold`)로 가독성을 살리고, 크기는 lg 사이즈의 기본 패딩과 간격만으로 목표치인 151x36px에 근접시켰다. 픽셀을 정확히 맞추기 위해 임의값을 박는 대신, 시스템 안의 값들 조합으로 근사한 것이다.

- 테마 토글에 AnimatedThemeToggler 통합(원형 확산 전환)
  - `@maxflow/ui/staging/animated-theme-toggler`를 재사용해 ThemeToggle의 CSS 크로스페이드를 View Transitions API 기반 clip-path 확산 애니메이션으로 교체했다. 클릭한 지점에서 원이 퍼지며 테마가 바뀐다.
  - 테마 소스를 둘로 만들지 않는 게 관건이었다. AnimatedThemeToggler의 제어 모드(`theme`/`onThemeChange`)가 기존 localStorage와 CustomEvent 브로드캐스트 경로(`apply`)를 그대로 타도록 lib/theme.ts에 `setTheme(theme)`를 추가해 연결했다. 애니메이션만 바꾸고 상태 관리는 손대지 않는다.
  - 함정이 하나 있었다. AnimatedThemeToggler는 forwardRef가 아니라 자체 `<button>`을 직접 렌더한다. 그래서 Tooltip.Trigger(render prop)가 요구하는 ref를 못 받아 툴팁 앵커링이 깨진다. host span으로 감싸 해결했다.
  - 시각은 기존 헤더 아이콘(size-8, rounded-lg)에 맞춰 className만 st-* 토큰과 스케일로 오버라이드했다. 임의값은 넣지 않았다.

- 사용 예제 코드 폰트 축소 + 관련 컴포넌트 위 1행으로 이동
  - 코드블록 폰트를 속성 패널과 같은 `text-step-n2`로 맞췄다. 같은 페이지에서 같은 성격의 정보가 다른 크기로 보이면 위계가 잘못 읽힌다.
  - "사용 예제" 섹션을 좌측 칼럼(히스토리 옆)에서 페이지 하단 "관련 컴포넌트" 바로 위로 옮겼다. import문과 JSX를 한 행(라벨 + 인라인 코드 + 복사 버튼)으로 압축하고, 긴 코드는 줄바꿈 대신 가로 스크롤로 처리했다. 사용 예제는 훑어보다가 복사하는 것이지 읽는 게 아니라, 세로 공간을 길게 차지할 이유가 없다.

- 사용 예제 라벨을 관련 컴포넌트와 같은 위계로
  - 자리를 옮기고 나니 라벨이 span/`text-step-n2`라 바로 아래 "관련 컴포넌트"(h3/`text-step-1`)보다 작아 하위 항목처럼 보였다. 같은 레벨의 섹션 제목이므로 h3/`text-step-1`로 올려 크기·굵기·색을 동일하게 맞췄다.

## 정리

Figma를 코드로 옮기는 작업에서 반복해서 부딪히는 건 결국 "시안이 말하는 값"과 "시스템이 가진 값"의 충돌이다. 오늘 그룹 생성 버튼이 딱 그 사례였다. 시안은 11px ExtraBold에 151x36px이라고 말했는데, 이 저장소는 타이포를 step 스케일로만 다루고 11px에 해당하는 스텝도 ExtraBold도 표준에 없다.

두 번에 걸쳐 답을 바꾼 게 오히려 기록으로는 정직하다. 처음에는 Figma 노드 스펙을 그대로 따랐고(높이·패딩·아이콘·굵기·그림자), 그다음에 그 굵기와 크기가 스케일 밖이라는 걸 인정하고 표준 스케일로 되돌리면서 목표 픽셀은 lg 사이즈 기본 패딩 조합으로 근사시켰다. 결과 픽셀이 몇 px 어긋나는 것보다 그 버튼 하나만 시스템 밖의 값을 쓰는 게 더 비싸다는 판단이다. 임의값 하나가 들어가면 다음 사람은 그걸 근거로 또 하나를 넣는다.

테마 토글에서 얻은 건 좀 다른 종류다. 이미 만들어둔 컴포넌트를 가져다 쓰는데도 두 가지를 조심해야 했다. 하나는 상태 소스를 늘리지 않는 것이다. AnimatedThemeToggler에 자체 테마 상태가 있는데 그걸 쓰면 localStorage와 CustomEvent 브로드캐스트가 이중화된다. 제어 모드로 붙여 기존 `apply` 경로를 그대로 타게 한 이유다. 다른 하나는 forwardRef 여부였다. 자체 `<button>`을 직접 렌더하는 컴포넌트는 render prop 기반 Tooltip.Trigger와 못 만난다. 라이브러리 컴포넌트를 만들 때 ref를 흘려보내는지 아닌지가 나중에 이런 조합 가능성을 정한다.

상세 페이지의 사용 예제는 두 커밋에 걸쳐 자리와 위계를 맞췄는데, 두 번째가 필요했던 이유가 재밌다. 자리를 옮기기 전에는 좌측 칼럼 안에서 상대적으로 적당한 크기였는데, 옮긴 뒤에 새 이웃(관련 컴포넌트)이 생기면서 그 이웃과의 관계에서 다시 어긋났다. 타이포 위계는 절대값이 아니라 옆에 무엇이 있느냐로 정해진다는 걸 다시 확인한 셈이다.
