# 배선과 관계를 갈라 둔 이유

> 흐름 지도에는 컴포넌트끼리 잇는 간선이 있다. 그런데 "이 화면에서 저 화면으로 간다"는 설명은 배선이 하나도 없어도 성립해야 한다. 오늘 이 둘을 같은 층에 섞지 않고 갈라 둔 결정을 내렸고, 그 위에 조망에서 출발하는 시연 지도를 얹었다. 하루의 시작은 반대로 어제 넣은 진행 단계 표시를 통째로 되돌리는 일이었다.

## 배경

흐름은 화면을 순서대로 엮어 "제품이 이렇게 흘러간다"를 말하는 물건이다. 지금까지 흐름 지도가 표현할 수 있는 건 컴포넌트 사이 배선뿐이었다. 그런데 배선은 시연 런타임의 입력이다. 핫스팟을 그리고 action을 주입하고 노드가 사라졌는지 판정하는 데 쓰인다. 화면과 화면의 관계를 여기에 섞으면 nodeId 없는 개체가 그 판정 전부에 분기를 떠안긴다.

동시에 흐름 만들기 자체가 다른 둘과 어긋나 있었다. 컴포넌트와 페이지는 작성기로 만드는데 흐름만 이름 입력 한 칸이었다. "여기선 다른 방식"이라는 신호가 되는데, 실제로도 흐름 만들기는 페이지를 고르는 일이라 작성기가 맞았다.

그리고 어제 넣은 진행 단계 표시가 있었다. 편입에서 의도, 배선, 인수인계로 이어지는 4단계를 UI가 보여주는 것인데, 새벽에 그걸 되돌리는 것으로 오늘이 시작됐다.

## 핵심 내용

### 개별 작업 기록 (시간순)

- 흐름 진행 단계 표시 제거 + 헤더·캔버스 컨트롤 ghost 전환
  - 진행 단계를 되돌렸다. 완료 규칙을 UI가 고정하면 기획자가 의도를 적는 게 아니라 체크를 채우게 된다는 지적을 받아들였다. 도구가 완료를 정의하면 사람이 그 정의에 맞춰 일하게 되고, 기획 의도가 오염된다.
  - 같은 커밋에 함께 들어갔던 헤더 2줄 구성과 보기 설정의 캔버스 이동은 그대로 뒀다. 되돌리는 것과 남기는 것을 커밋 단위가 아니라 판단 단위로 갈랐다.
  - 헤더 우상단 4개 버튼을 모두 ghost로 바꿨다. 시연 시작만 잉크로 채워져 있었는데 혼자 튀어 위계가 잘못 읽혔다.
  - 인수인계 3종(스택, 프롬프트 복사, 즉시 실행)을 케밥 하나로 접었다. 셋을 다 펼치면 시연·편입·삭제와 섞여 여섯 개가 한 줄에 서고, 무엇을 누를지 고르는 데 시간이 든다. 스택은 메뉴 안 라디오로 두어 값을 보고 바로 복사로 이어지게 배치했다.
  - 캔버스 우상단 보기 설정의 그룹 껍데기도 제거했다. 안쪽이 이미 알약이라 겉을 한 겹 더 두르면 테두리가 이중으로 겹쳐 보였다.

- 지도 위 컨트롤 높이 통일 + 아이콘 전용화
  - 경로, 화면별, 요약/상세, 자동 정렬이 제각각 높이라 캔버스 위에서 줄이 안 맞았다. 넷 다 28px로 맞추고, 라벨이 굳이 필요 없는 둘은 아이콘만 남겼다. 캔버스 위 컨트롤은 지도를 가리지 않는 게 우선이라 이름은 툴팁이 맡는다.
  - 기능 검증 중 채워진 값(별칭, 아이콘, 경로, 컴포넌트 메모, 섹션, 좌표)이 담긴 흐름 JSON을 데모 데이터로 남겼다. 새 스키마가 실제로 어떻게 쓰이는지 보여주는 유일한 예시라서다.

- 첫 사용 흐름 배선 시도와 되돌림
  - 요금제 선택을 시작 화면으로 두고 세 플랜의 선택 버튼에서 워크스페이스 대시보드로 이어지는 간선 3개를 연결했다가, 곧바로 되돌렸다.

- 흐름 즉시 생성을 컴포넌트·페이지와 같은 작성기 구조로 통일
  - 제출은 두 단계다. 클라이언트가 흐름 생성과 화면 편입까지 끝내고, 그다음 에이전트에게 배선을 맡긴다. 편입을 에이전트에 넘기면 서버가 하는 버전 박제와 스냅샷 기록이 통째로 빠져 모든 화면이 스냅샷 없음 상태가 된다. 순서를 바꿀 수 없는 이유가 여기 있다.
  - 페이지 없이 전송하면 막되 왜 막혔는지 가리킨다. 좌하단 페이지 버튼이 붉어지며 툴팁이 뜬다. 막기만 하면 버튼이 고장 난 것처럼 읽힌다. 이를 위해 Tooltip에 제어형 open을 추가했다.
  - 페이지 미리보기는 컴포넌트용보다 넓게 뒀다. 목업끼리 겉모습이 비슷해 구조 스케치와 신원(slug·버전·수정자·피드백)까지 봐야 구분된다. 패널 미리보기 폭이 하드코딩이라 소비처가 못 넓히던 것을 prop으로 열었다.
  - 중첩 피커 Escape 버그도 함께 고쳤다. 피커와 작성기가 같은 document 캡처를 듣는데 등록 순서상 작성기가 먼저 실행돼 `stopPropagation`이 안 통했다. 열려 있는 동안 표식을 남기고 작성기가 양보하게 했다. 컴포넌트 피커에도 있던 같은 결함이다.

- 흐름 생성 경고 표현을 세 번 고쳤다
  - 처음엔 페이지 없이 전송하면 작성기가 좌우로 한 번 흔들리게 했다(아이폰 암호 오류 표현). 붉은 버튼과 툴팁만으로는 눌렸는지조차 모호했다. 채팅 입력의 흔들림 규약과 키프레임을 그대로 가져왔다. 두 작성기의 "막혔다" 표현이 다르면 같은 도구로 안 읽힌다.
  - 페이지 고르기 아이콘을 겹친 종이 모양에서 레이아웃 템플릿 모양으로 바꿨다. 겹친 종이는 "페이지 목록"으로 안 읽힌다.
  - 마지막으로 경고 색을 아이콘 버튼에서 툴팁으로 옮겼다. 버튼을 물들이면 "이 버튼이 잘못됐다"로 읽히는데, 잘못된 건 버튼이 아니라 아직 안 한 일이다. 위험색 대신 주황을 쓴 것도 같은 이유다. 되돌릴 수 없는 일이 아니라 순서를 알리는 것뿐이다. 툴팁은 아래로 띄웠다. 작성기가 화면 아래쪽에 뜨고 위쪽엔 칩 줄이 있어 위로 띄우면 방금 고른 페이지들을 가린다.

- 빈 흐름 만들기 + 페이지 피커 뷰포트 회피 배치
  - 작성기는 페이지를 골라야 제출되므로 빈 채로 시작할 길이 없었다. 흐름 목록 히어로에 '빈 흐름 만들기'를 주 버튼과 같은 크기로 테두리만 두어 추가했다. 테두리 1px만큼 py를 덜어 두 버튼 높이를 맞췄다.
  - 페이지 고르기 팝오버가 항상 위로만 펴지던 것을 기본 아래로 바꾸고 뷰포트에 잘리면 뒤집게 했다. 배치 계산은 이미 같은 일을 하던 컴포넌트 피커에서 훅으로 뽑아 둘이 공유한다.

- 흐름 삭제 대화상자: 이름 입력 게이트 + 대비 색 + 용어 통일
  - 삭제 버튼이 빨간 배경에 검정 글씨였다. `text-st-destructive-foreground` 토큰이 CSS에 매핑이 아예 없어 클래스가 아무것도 만들지 못하고 글자색이 상속돼 검정이 된 것이었다. 레포에서 이 클래스를 쓰던 곳은 이 버튼 하나뿐이었다. 이미 같은 짝을 쓰던 선례를 따라 고쳤다.
  - 이름을 그대로 적어야 삭제가 열린다. GitHub의 위험 조작 확인과 같은 방식이다. 확인 버튼 하나면 "예"를 누르는 게 근육기억이 되어 정작 지우면 안 되는 걸 지운 다음에야 알아챈다. 옮겨 적는 동안 무엇을 지우는지 한 번 더 읽게 하는 것이 이 게이트의 전부다. 비교는 앞뒤 공백만 턴 정확 일치로 뒀다. 대소문자를 접으면 옮겨 적는 행위가 헐거워진다.
  - **"배선"을 "연결"로 통일**했다. 흐름 카드가 이미 "연결 N"으로 세고 있어 같은 것을 두 이름으로 부르고 있었다. 화면 라벨과 복사되는 프롬프트 문장까지 함께 맞췄다.
  - 게이트가 붙으면서 라우트가 300줄 정책을 넘어 대화상자를 별도 파일로 분리했다. 확인 절차는 그 자체로 한 덩어리이기도 하다.

- 흐름 지도에 화면과 화면 사이 대표 관계와 태그 추가
  - 이 묶음의 중심이다. 컴포넌트 배선과 별개 레이어로 화면 사이 관계를 1급 개체로 뒀다. 간선은 시연 런타임의 입력이라 nodeId 없는 개체를 섞으면 그 전부가 분기를 떠안는다. 관계는 배선이 하나도 없어도 성립해야 하는 설명 레이어라 갈라 뒀다.
  - 타입과 정규화, 무결성 검사, 패치를 새로 만들고, 지도에는 커스텀 엣지로 태그 배지를 그린다. 요약 뷰는 겹치는 컴포넌트 선을 접어 개수만 배지에 남긴다.
  - 요약 뷰의 out/in 핸들은 대표 관계 전용으로 돌리고, 상세 카드 머리에 관계 전용 핸들을 신설했다. 통합 프롬프트에도 "화면 사이 관계" 표를 전이 표보다 먼저 싣는다.
  - 부수적으로 요약 뷰에서 끌면 nodeId "out"짜리 유령 배선이 생기던 문제가 사라졌다. 스냅샷에 없는 id라 곧바로 "노드 사라짐"으로 뜨던 선이다.

- 시연에 흐름 지도 단계 추가
  - 시연이 시작 화면으로 곧장 들어가면 "이 흐름이 전체적으로 어떤 모양인가"를 말할 자리가 없다. 발표는 대개 조망에서 출발해 한 화면으로 내려간다. 그 첫 단계를 만들었다.
  - `/flows/<slug>/play` 라우트로 크롬 없는 전체화면을 띄운다. 좌측은 read-only 캔버스, 우측은 화면별 메모가 흐름 순서대로 놓인다. 노드를 클릭하면 기존 화면 시연으로 그대로 진입하고 이후 동작은 바뀌지 않는다.
  - Esc는 한 단계 위로 간다. 화면 시연에서 시연 지도로, 시연 지도에서 흐름 편집으로.
  - 이어가기 상태(요약/상세, 뷰포트, 방문 표시)는 모듈 스토어와 sessionStorage에 뒀다. 지도와 화면 시연이 다른 라우트라 React state로는 못 든다. 공통 부모가 없기 때문이다.
  - 요약과 상세는 노드 크기가 두 배 넘게 달라 뷰포트를 이어 쓰면 카드가 화면 밖으로 밀린다. 런타임 `fitView()`는 통하지 않았다. 노드 id가 그대로라 xyflow가 재측정을 "초기화 안 됨"으로 보지 않아 크기 갱신 시점을 잡을 신호가 없다. 캔버스를 key로 다시 세우는 쪽을 택했다.
  - 흐름 라우트 매칭은 순서가 곧 규칙이라(`/play`가 배선보다 먼저) 별도 모듈로 묶었다. 나란한 정규식으로 두면 그 순서가 우연처럼 보이고 한 줄만 옮겨도 다른 화면이 뜬다.

- 관계 태그 자동 포커스·인스펙터 시인성·이름 우선순위 정리
  - 사용자 피드백 3건을 반영했다. 관계를 끌어서 만들면 인스펙터가 그 관계로 자동 열리고 태그 칸이 바로 입력 가능한 상태가 된다. 끌기, 클릭, 클릭 세 동작이 하나로 줄었다. 추가가 비동기라 관계가 실제로 목록에 도착한 순간에만 신호를 지운다. 곧바로 지우면 인스펙터가 마운트되기 전에 신호가 사라져 한 번도 못 걸린다.
  - 인스펙터 입력을 작성기 스타일 박스로 통일했다. 기존의 "평소엔 텍스트, 누르면 입력"은 값을 읽는 자리에는 맞지만 인스펙터는 고치러 오는 자리다. 읽기와 편집 두 상태에 같은 박스를 줘서 누를 때 덜컹이지 않는다. 패널 폭도 1.2배로 넓혔다.
  - 시작 화면의 테두리 강조색을 없앴다. 선택하지 않았는데도 "지금 골랐다"처럼 읽혀 실제 선택 상태와 헷갈렸다. 시작 표시는 배지와 부제 문구가 맡는다.
  - 화면 이름 표시를 `흐름 별칭 > 페이지 제목 > slug` 하나로 통일했다. 화면 시연 Dock, 전체화면 미리보기, 배선 머리줄, 목적지 피커 네 곳이 이 규칙을 건너뛰고 페이지 원본 제목을 직접 그려 지도와 시연에서 이름이 서로 달라 보였다.

- 흐름 지도 fitView가 편집할 때마다 줌·위치를 리셋하던 문제
  - PATCH가 한 번 돌면 흐름이 새로 오고 노드가 통째로 재생성돼 measured가 없어진다. 초기화 여부가 false에서 true로 다시 튀면서 fitView가 매번 재호출돼, 아이콘 하나만 바꿔도 사용자가 잡아 둔 줌과 위치가 제멋대로 리셋됐다. ref로 최초 1회만 맞추도록 잠갔다. 다시 맞추고 싶으면 좌하단 fit 버튼이 있다.

- 흐름 데이터 정리
  - 오늘 만든 복제 기능으로 "테스트" 흐름을 복제해 사본으로 만들고(섹션과 요약 추가) 원본을 삭제했다. 복제해 둔 페이지들을 잇는 새 흐름도 하나 만들었다.

## 정리

오늘 흐름 쪽에서 내린 결정 중 가장 오래 남을 건 **배선과 관계를 같은 층에 섞지 않은 것**이다. 둘 다 지도 위의 선이고 화면상으로는 비슷하게 생겼지만, 배선은 시연 런타임이 실행하는 명령이고 관계는 사람에게 설명하는 문장이다. 배선에는 nodeId가 반드시 있어야 하고 관계에는 없어도 된다. 하나로 합치면 nodeId 없는 개체가 핫스팟 그리기, action 주입, 노드 사라짐 판정 전부에 분기를 하나씩 더한다. 지금 합치면 편하고 나중에 갈라내려면 그 분기를 다 걷어내야 한다.

하루의 시작이 **어제 만든 걸 되돌리는 일**이었던 것도 기록해 둘 만하다. 흐름의 진행 단계 표시는 기능적으로는 멀쩡했다. 문제는 "UI가 완료를 정의하면 사람이 그 정의에 맞춰 일한다"는 것이었다. 기획자가 의도를 적는 자리에 체크박스를 두면 의도 대신 체크가 채워진다. 도구가 사람의 사고 방식을 결정하는 자리가 있고, 이건 코드 품질로는 안 잡히는 종류의 문제다. 되돌릴 때 같은 커밋에 들어 있던 다른 변경은 남긴 것도 의도적이었다. 되돌림의 단위는 커밋이 아니라 판단이다.

**막는 것과 왜 막혔는지 알려주는 것은 다른 일**이라는 것도 오늘 세 번 고쳐가며 배웠다. 페이지 없이 흐름을 만들려 할 때, 처음엔 그냥 막았고, 다음엔 버튼을 붉게 물들였고, 그다음엔 흔들었고, 마지막엔 색을 툴팁으로 옮겼다. 버튼을 물들이면 "이 버튼이 잘못됐다"로 읽히는데 잘못된 건 버튼이 아니라 아직 안 한 일이다. 색 하나 옮기는 게 의미를 통째로 바꾼다.

그리고 **같은 것을 두 이름으로 부르지 않기**가 오늘 하루 종일 반복됐다. "배선"과 "연결"을 통일했고, 화면 이름 표시 규칙을 네 곳이 건너뛰고 있던 걸 하나로 모았다. 규칙을 만드는 것보다 규칙을 건너뛴 자리를 찾는 게 늘 더 오래 걸린다.
