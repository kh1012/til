# 사용자 행위 로깅 스키마 설계 - undo/redo는 노이즈가 아니라 라벨링된 시그널

> CAD 도면 툴에서 사용자가 되돌리고 다시 그리는 과정을 AI가 이해할 수 있는 로그로 남기려면, "무엇을 기록할지"보다 "왜 되돌렸는지가 왜 사라지는지"부터 봐야 했다.

## 배경

maxflow(도면 편집 웹앱)에 사용자 행위 로깅 시스템을 붙이는 작업이었다. 사용자가 중심선을 땄다가 되돌리고 다시 그려서 완성하는 과정을, AI 에이전트가 나중에 읽고 "이 흐름은 이렇게 푸는 게 낫다"는 제안을 줄 수 있는 형태로 남기고 싶다는 요구였다. 착수 전에 먼저 기성 서비스(Sentry, PostHog, OpenReplay, LogRocket, Amplitude)로 해결 가능한지부터 검토했다.

## 핵심 내용

**왜 기성 툴로 안 되는가.** 요구사항은 사실 두 가지로 쪼개진다 — ① 수집·저장·재생·시각화 인프라는 성숙한 시장이라 사면 된다. ② "중심선을 3번 되돌리고 다시 땄다 → 이렇게 하는 게 낫다"는 도메인 의미 해석은 아무도 안 판다. "중심선"·"재작업" 같은 개념은 maxflow 안에만 존재해서 외부 서비스가 알 방법이 없다.

Sentry를 기각한 진짜 이유도 "에러 전용이라서"가 아니라 **분석 단위 자체가 다르기 때문**이었다. Sentry의 단위는 "실패한 순간"이고, 여기 필요한 단위는 "완성까지 간 경로 전체"다. 되돌리고 다시 그리는 행위는 Sentry 관점에서는 아무 일도 일어나지 않은 것과 같다. rrweb 계열 화면 리플레이도 캔버스를 이미지로 스냅샷 떠서 도면 앱에는 비용이 폭증해 이벤트만 받는 쪽으로 판단했다. 진짜 참고할 분야는 product analytics가 아니라 **프로세스 마이닝**(XES 표준의 `case_id`/`activity`/`timestamp` 3튜플, variant analysis, conformance checking)이었다.

**가장 중요한 발견은 코드 안에 있었다.** `modeler-edits.ts` 주석을 보다가, undo/redo가 있는 구조라 연산 스트림 대신 상태 스냅샷 비교 방식을 쓰고 있다는 걸 발견했다. 그 결과 "무엇을 왜 되돌렸는지"가 로그에서 증발하고 있었다. 여기서 나온 통찰: **되돌림은 노이즈로 걸러낼 대상이 아니라, 사람이 직접 라벨링해준 학습 신호다.** 사용자가 되돌렸다는 사실 자체가 "이 시도는 틀렸다"는 정답 라벨이나 다름없다.

이 통찰에서 스키마 설계 원칙 4가지가 나왔다:
1. 좌표 대신 의도를 기록한다.
2. undo를 별도 op로 취급하지 않고, 같은 op의 phase로 처리한다 (스키마의 핵심).
3. via(자동 처리 대비 사람이 얼마나 직접 고쳤는가)를 남긴다.
4. case 경계(=DXF 파일명)와 결과 라벨을 남긴다.

zod 스키마도 `args: z.record(SCALAR)`로 정해서 좌표를 직접 넣는 실수가 **타입 레벨에서 컴파일 에러**가 되게 막았다. `op` 필드는 처음엔 새 어휘를 만들려 했지만, CAD 패키지(`packages/cad/web`)에 이미 `CadCommands`라는 70개 도메인 커맨드 액션 유니온이 있다는 걸 뒤늦게 발견해서 "새로 정의해야 한다"는 초기 판단이 틀렸음이 드러났다. 필드명도 `op`에서 `action`으로 바꿨는데, 코드베이스 리듀서 타입이 이미 `Action`이라 스키마 어휘를 코드 어휘에 맞춘 것이다.

세션 막바지에는 cad-web의 "변경 이력" 탭(`ReviewResolution`)이 이미 부분적 결정 로그였다는 것도 발견했다. 다만 폴더를 열 때마다 초기화되고 append가 아니라 덮어쓰기로 저장돼 사실상 "로그가 아니라 스냅샷"이었다. 그래서 1층 설계는 신규 구축이 아니라 "반쯤 만들다 만 걸 완성하는 것"으로 재정의됐다.

## 정리

로깅 시스템을 새로 짤 때 "어떤 필드를 기록할까"부터 시작하면 undo/redo 같은 사용자 정정 행위를 노이즈로 취급하기 쉽다. 하지만 사람이 자기 행동을 되돌렸다는 사실 자체가 이미 라벨링된 데이터라는 관점으로 보면 스키마 설계가 완전히 달라진다. 또 하나 배운 점은 "새 어휘가 필요하다"는 판단을 내리기 전에 기존 코드(리듀서의 `Action` 타입, `CadCommands` 유니온)를 먼저 뒤져야 한다는 것 — 이미 있는 걸 다시 만들 뻔했다.
