# 모양을 통일하니 버그가 드러났다

> 하나의 화면씩 만들다 보면 같은 역할의 컨트롤이 화면마다 다른 모양을 갖게 된다. 새벽에 한 일은 그 흩어진 모양들을 하나의 규칙으로 수렴시키는 것이었는데, 통일하려고 코드를 한자리에 모으는 순간 그동안 안 보이던 결함들이 같이 튀어나왔다.

## 배경

하네스는 컴포넌트 갤러리, 페이지 플레이그라운드, 흐름 편집기가 각각 다른 시기에 붙어 만들어졌다. 그래서 "여럿 중 하나를 고른다"는 똑같은 동작이 화면마다 다른 UI로 구현돼 있었다. 컴포넌트 갤러리는 Selector 팝오버를 쓰는데, 페이지·흐름 목록의 정렬은 개별 pill 버튼이 나란히 늘어서 있고, 흐름 상세의 프레임 선택은 또 다른 pill 3개였다.

모양도 마찬가지였다. 어떤 버튼은 `rounded-full`, 어떤 건 `rounded-md`, 카드는 `rounded-xl`, 폰트 크기는 `text-step-n1`과 `n2`가 섞여 있었다. 각각을 만들 땐 그 화면 안에서 자연스러웠지만, 나란히 놓고 보면 "초기화 버튼만 왜 저러지" 같은 게 눈에 걸린다.

pilled 컨셉(원형·pill·큰 반경)을 기준으로 전 화면을 훑기로 했다.

## 핵심 내용

### 개별 작업 기록 (시간순)

- 컴포넌트 갤러리 툴바 pilled 통일 + 필터 0건 옵션 표시
  - Selector 트리거, 팝오버 옵션, deprecated 체크박스, 밀도 토글, 뷰 토글, 이력·공유 아이콘 버튼을 전부 `rounded-full`로 통일하고 폰트도 `text-step-n2`로 맞췄다. 초기화 버튼만 다르게 보이던 게 여기서 해소됐다.
  - 겸사겸사 잡은 게 더 중요했다. "실행 중"·"오늘 수정됨" 필터가 해당 항목 0건이면 팝오버 목록에서 아예 사라져 있었다. 사용자 입장에선 "왜 안 보이지"로 읽힌다. Selector에 `disabled` 옵션을 추가해, 0건이어도 목록엔 남기고 회색 비활성 상태로 표시하도록 바꿨다.

- 리스트 카드 radius 확대
  - 컴포넌트·페이지·흐름 3종 목록 카드를 `rounded-xl`에서 `rounded-2xl`로 올렸다. pilled 컨셉과 결을 맞추는 단순 작업이다.

- 컴포넌트 상세 액션 버튼·하단 섹션 pilled 통일
  - 고정, 프롬프트 3종 복사, 즉시 실행, Storybook, 케밥 버튼을 원형 또는 pill로 바꿨다. 속성 InfoTable과 사용 예제 박스는 `rounded-2xl`로 카드와 같은 반경을 줬다.

- 페이지 플레이그라운드·흐름 상세 pilled 마무리
  - 통합·피드백 프롬프트 복사 버튼(커스텀 radius를 쓰고 있었다), 전체 레이아웃 피드백 버튼, 줌 ButtonGroup, 삭제 확인 다이얼로그 버튼, 버전 목록 항목, 흐름 캔버스 패널까지 나머지 화면과 같은 규칙으로 맞췄다. 여기서 pilled 훑기가 화면 전체를 한 바퀴 돈다.

- 터미널 바로보기 배너 컴팩트화 + 로그 hover 피드백
  - "바로보기" 배너 패딩을 줄이고 버튼을 채움 스타일에서 흰 글자 텍스트 버튼으로 바꿔 더 핏하게 만들었다.
  - 로그의 접기·펼치기 줄(`CollapsibleLine`)에 hover 배경을 얹어 클릭 가능한 영역이라는 걸 알렸다. 이 hover 처리는 몇 시간 뒤에 다시 뒤집힌다.

- 터미널 로그 tool_call + tool_result 병합 + hover 텍스트색 전환
  - 지금까지 로그는 `$ Read` 한 줄과 `→ (파일 내용 그대로)` 한 줄로 나뉘어 찍혔다. 결과가 파일 텍스트나 커맨드 출력 원문이라 자연어 문장이 아니고, 그게 그대로 로그 폭을 차지했다.
  - `toolPairSummary`를 새로 만들어 호출과 결과를 `$ Read <경로> 읽음` 한 줄로 압축하고, 전체 내용은 그 줄을 클릭해 펼치게 했다. 결과 원문에서 동사를 뽑을 수 없으니 도구 이름을 키로 한 `TOOL_VERB` 맵(Read는 "읽음", Bash는 "실행함" 등)을 직접 두고, 목록에 없는 도구(MCP 등)는 "완료함"으로 폴백한다. 결과가 아직 안 왔으면 `…`이다.
  - hover 표현을 배경(`bg-st-muted`)에서 텍스트 색(`text-st-primary`)으로 바꿨다. 로그 줄은 이미 6개 톤(info·warning·muted·destructive·success·default)으로 색이 나뉘어 있어서, 배경을 쓰면 어떤 톤과는 겹쳐 보인다. 텍스트 색 전환은 어느 톤과도 안 겹쳐 항상 눈에 띈다. `.agent-log-surface`에서는 인디고로 복원한다.
  - 경로가 없는 도구(Bash 등)는 `$ Bash 실행함`만으로는 뭘 했는지 안 보이니, 결과 첫 줄을 60자까지 잘라 옅은 회색으로 보충한다. Read는 서버 어댑터에 `filesChanged`와는 별개인 `readPath` 필드를 새로 추가해 실제 읽은 파일 경로를 보여준다. 읽기는 파일을 바꾸지 않으니 기존 변경 파일 목록에 실을 수 없었다.

- Selector 팝오버 뷰포트 대응 + 트리거·옵션 폰트/간격 통일
  - Selector 팝오버가 `right-0` 우측 정렬 고정이었다. 컴포넌트 갤러리 툴바처럼 화면 오른쪽에 있는 트리거에서는 문제가 없었는데, 흐름 상세 프레임처럼 화면 왼쪽에 가까운 트리거에서는 팝오버가 뷰포트 밖으로 나갔다.
  - 기본을 좌측 정렬로 바꾸고, 그 상태에서 오른쪽이 넘치면 `useLayoutEffect`로 `getBoundingClientRect().right`를 재서 우측 정렬로 뒤집는다. `useEffect`가 아니라 `useLayoutEffect`인 게 핵심이다. 브라우저가 화면을 그리기 전에 보정이 끝나 깜빡임이 없다.
  - 옵션 행 폰트가 트리거보다 한 단계 컸던 것(n1 대 n2)도 n2로 맞추고, 옵션 사이에 `gap-px`를 넣어 서로 붙어 보이던 걸 1px 뗐다.

- Pages/Flows 정렬 Selector 전환 + 사이드바 탭·데모 프리뷰 pilled
  - 페이지·흐름 목록의 정렬(최근 수정순/이름순) 개별 버튼을 컴포넌트 갤러리와 같은 Selector 팝오버로 바꿨다. 여기가 이번 훑기에서 코드 라인이 실제로 줄어든 자리다.
  - 옆에 있는 "전체" 칩 폰트도 Selector와 맞춰(n1에서 n2로) 나란히 놓였을 때 크기가 달라 보이던 걸 없앴다. 페이지 플레이그라운드 사이드바 탭(피드백/정보)은 `rounded-full`로, 컴포넌트 상세 데모 프리뷰 박스는 카드와 같은 반경으로 맞췄다.

- 흐름 상세 프레임 선택 Selector 전환 + 삭제 모달 줄바꿈
  - "화면별/FHD/QHD" 개별 pill 3개를 Selector 팝오버 하나로 바꿨다. 문제는 "화면별"이 오버라이드 없음, 즉 `frame: null`이라는 것이었다. `Selector<T extends string>`은 null을 값으로 못 받는다.
  - `FRAME_AUTO = "__auto__"` sentinel을 두고 경계에서만 변환한다(`value={flow.frame ?? FRAME_AUTO}`, `onChange`에서 다시 null로). 컴포넌트 갤러리 분류 Selector가 `CATEGORY_ALL`로 이미 쓰던 것과 같은 패턴이라 새로 만든 규칙은 아니다.
  - 흐름 삭제 확인 문구도 두 문장이 각각 한 줄에 들어가도록 `<br>`로 강제 줄바꿈했다.

## 정리

이 새벽 작업의 표면적 목표는 "모양 맞추기"였는데, 실제로 얻은 것의 절반은 **통일하려고 코드를 한자리에 모으는 과정에서 드러난 결함**이었다. Selector 팝오버의 `right-0` 고정은 원래 쓰이던 자리(오른쪽 툴바)에서는 영원히 안 드러났을 버그다. 흐름 상세라는 왼쪽 트리거에 같은 컴포넌트를 갖다 붙이는 순간 바로 튀어나왔다. 0건 필터가 목록에서 사라지던 것도, 툴바를 한 줄씩 다시 읽지 않았으면 그대로 남았을 것이다. 일관성 작업은 리팩터링처럼 "기능은 그대로"라고 여겨지지만, 공용 컴포넌트를 새 문맥에 넣는 건 사실 그 컴포넌트에 대한 테스트를 한 번 더 돌리는 일이다.

**같은 동작은 같은 컴포넌트로 수렴시켜야 개선이 한 번에 퍼진다**는 것도 확인했다. 정렬 버튼이 화면마다 별개 코드였다면 뷰포트 대응은 세 번 짜야 했다. Selector 하나로 모아 둔 덕에 `useLayoutEffect` 보정 한 번이 프레임 선택, 정렬, 분류 필터 전부에 동시에 적용됐다. 반대로 통일을 미뤘다면 각 화면의 pill 버튼들은 계속 조금씩 다른 방향으로 갈라졌을 것이다.

sentinel 값은 타입 경계에서 어쩔 수 없이 생기는 타협인데, **이미 레포에 있는 같은 타협을 따르는 것과 새로 발명하는 것은 다르다.** `Selector<T extends string>`이 null을 못 받는 건 제네릭 제약이라 고치려면 컴포넌트 시그니처를 건드려야 한다. 그 대신 `CATEGORY_ALL`이 이미 쓰던 sentinel 패턴을 그대로 가져와서, 이 레포에서 "값 없음"은 sentinel 문자열로 표현한다는 규칙이 하나로 유지된다. 주석에 그 선례를 명시해 둔 것도 그래서다.

터미널 로그 병합은 결이 조금 다르다. 여기서 바꾼 건 모양이 아니라 **읽히는 단위**였다. 호출과 결과를 두 줄로 나눠 찍는 건 데이터 구조를 그대로 화면에 옮긴 것이고, 사람이 로그를 읽을 때 궁금한 건 "무슨 도구로 무슨 파일에 무엇을 했나" 한 덩어리다. 그런데 결과 원문에서는 "무엇을 했나"에 해당하는 자연어가 안 나온다. 파일 내용이나 커맨드 출력이지 문장이 아니기 때문이다. 그래서 동사를 도구 이름에서 만들어 붙였다. 데이터가 안 주는 정보를 화면 쪽에서 채워 넣는 건 보통 냄새가 나는 선택인데, 이 경우엔 도구 이름이라는 안정된 키가 있어서 매핑 테이블 하나로 정리됐다.

마지막으로 hover 표현이 몇 시간 만에 배경에서 텍스트 색으로 뒤집힌 것도 기록해 둘 만하다. **배경색은 유한한 자원이다.** 로그 줄이 이미 6개 톤을 배경 없이 글자색으로만 구분하고 있었으니, 거기에 hover 배경을 얹으면 톤에 따라 잘 보이기도 하고 안 보이기도 한다. 상태 표현 수단을 새로 고를 땐 그 화면이 이미 무엇으로 정보를 나르고 있는지를 먼저 세어 봐야 한다.
