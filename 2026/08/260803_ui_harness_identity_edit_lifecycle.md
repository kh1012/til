# 이름을 바꿀 수 없는 것에 이름을 붙이는 법

> 갤러리에서 물건을 고르는 순간에 뜨는 건 `global-nav-bar` 같은 원시 식별자뿐이라 무엇인지 알아볼 수 없었다. 그런데 그 이름은 딥링크·import 지정자·박제 스냅샷이 전부 가리키는 키라 바꿀 수 없다. 오늘 한 일의 절반은 "바꿀 수 없는 것 위에 바꿀 수 있는 층을 하나 더 두는" 결정이었고, 나머지 절반은 그 층이 화면 전부에 새는 곳 없이 흐르게 만드는 일이었다.

## 배경

하네스의 컴포넌트·페이지·흐름 셋은 지금까지 "만들고 본다"까지만 됐다. 만든 다음에 하고 싶은 일들이 통째로 비어 있었다. 베껴서 변형하고 싶으면 원본을 직접 고치거나 처음부터 다시 만들어야 했고, 이름이 마음에 안 들어도 고칠 수 없었고, 지우는 건 아예 길이 없었다.

특히 이름 문제는 편집 능력이 셋 다 제각각이라 더 뚜렷했다. 컴포넌트는 이름도 설명도 못 고쳤고, 페이지는 설명 필드 자체가 없었고, 흐름만 겨우 둘 다 있었다. 그래서 페이지에 컴포넌트를 얹거나 흐름에 페이지를 넣는 피커에서 무엇을 고르는지 알아볼 방법이 원시 식별자를 읽는 것뿐이었다.

여기에 새 기능을 붙이려면 먼저 정해야 할 게 있었다. 컴포넌트의 `name`은 페이지 노드 `type`, import 지정자, `/c/<name>` 딥링크가 가리키는 키이고, 무엇보다 `pages/.versions/`에 박제된 스냅샷에 박혀 있다. 진짜 rename은 흐름이 가리키는 과거 화면을 깨뜨린다. 이걸 인정하고 시작할지, 아니면 rename을 하려고 애쓸지가 오늘의 첫 갈림길이었다.

## 핵심 내용

### 개별 작업 기록 (시간순)

- 컴포넌트·페이지·흐름 복제
  - "이걸 베껴서 변형해보자"를 할 방법이 없어 원본을 직접 고치거나 처음부터 다시 만들어야 했다. 세 상세에 같은 버튼을 두고, 만들면 바로 그 상세로 이동한다.
  - 컴포넌트 복제본은 항상 `src/staging/<name>-draft/`로 간다. `"./staging/*"` 와일드카드 export가 이미 있어 바로 import해 쓸 수 있고, 공용에 두면 package.json과 배럴에 줄을 더해야 하며 같은 심볼 이중 export로 TS2308이 난다. 게다가 registry HMR 감시 대상이 `registry/entries`와 `ui/src/staging` 둘뿐이다.
  - 식별자는 안 바꿨다. 모듈이 다르면 충돌하지 않고 기존 클론 둘도 그렇다. 바꾸는 건 파일명, 상대 import 지정자, 스토리 title 셋뿐이다. 제목만은 겹치면 Storybook이 깨진다.
  - 함정 셋을 실제로 밟고 고쳤다. import는 `"./x"`뿐 아니라 `"./x.demo"`도 있어 뒤 문자에 점이 필요했고, 스토리 제목은 kebab이 아니라 PascalCase였고, `files[0]`은 반드시 본체여야 했다. import 경로와 Storybook kind를 그걸로 정하는데 readdir 순서면 `.demo`가 먼저 온다.
  - 정규화가 신규 필드를 조용히 버리는 함정도 함께 나왔다. pages의 `classify()`가 `derivedFrom`을 지금도 버리고 있었다. 이 함정은 오늘 하루 종일 반복해서 나온다.
  - 앞서 `context-menu-fit-draft`를 두 번 만들었다 두 번 되돌린 흔적이 남았는데, 그게 이 기능이 없어서 손으로 하던 일이었다.

- 하네스 레지스트리 엔트리를 prettier 직렬화 예외로 등록
  - `pnpm run check`가 prettier 베이스라인에서 깨지고 있었다. 갤러리 API가 레지스트리 엔트리를 `JSON.stringify(x, null, 2)`로 다시 쓰는데 prettier는 짧은 배열을 한 줄로 접길 원한다. 상태 변경, 복제, 히스토리 적재가 일어날 때마다 어긋나므로 한 번 포맷해도 다음 쓰기에서 또 깨진다.
  - 이미 등록돼 있던 `design/core/templates`나 OpenAPI 산출물과 같은 성격이라 `native-serializer`로 `.prettierignore`와 매니페스트에 등록했다. 포맷이 안 된 소스 세 개는 포맷하고, 다른 곳에서 이미 포맷돼 버린 200여 개 낡은 베이스라인 항목은 갱신했다. 나중에 이 베이스라인을 통째로 비운 뒤 남아 있던 문서 8건도 따로 포맷했다.

- 컴포넌트·페이지·흐름 이름·설명 제자리 편집 + 중복 차단
  - 오늘의 중심 결정이다. 컴포넌트 이름은 바꾸지 않고 `meta.displayName`을 새로 두어 덧씌운다. 표시는 `displayName ?? name`으로 읽는다. 페이지가 `title`+`slug`, 흐름이 `name`+`slug`로 이미 쓰던 구조와 같은 모양이 된다.
  - 폴백 규칙은 `displayNameOf()` 하나로 모았다. 갈라지면 같은 컴포넌트가 화면마다 다른 이름으로 불린다. 실제로 오늘 하루 이 규약을 건너뛴 자리가 여러 번 더 나왔다.
  - 표시명은 카드·행·검색·피커·캔버스 라벨까지 흐르되 원시 이름은 피커 키워드와 검색 건초더미에 남긴다. 개발자는 코드에서 쓰는 이름으로 찾는다.
  - 중복은 UI가 막는다. `InlineTextEdit`이 blur로 커밋하는 탓에 "저장 불가"를 두 갈래로 나눴다. Enter로 무효값을 저장하려 하면 편집 상태를 유지해 고칠 기회를 주고, 다른 곳을 눌러 나가면 되돌린다. blur에서도 붙잡으면 경고를 못 읽는 사용자가 칸에 갇힌다.
  - 페이지 `description`은 신설이라 `pages-store.ts`의 재구성 지점을 모두 짚었다. 알려진 필드만 다시 조립하는 파일이라 한 곳만 빠져도 저장은 되는데 읽을 때 조용히 사라진다. 클론 작업에서 `derivedFrom`으로 이미 겪은 함정이다.

- 헤더 검색창 한글 조합 깨짐 수정
  - "안녕" 대신 "ㅇㅏㄴㄴㅕㅇ"이 쌓였다. 검색어 소유는 라우트인데 값이 effect를 거쳐 오느라 change 이벤트 종료 시점엔 props가 한 글자 전이었고, React가 controlled input을 props에 맞춰 DOM value로 되돌리면서 IME 조합 버퍼가 매 글자 깨졌다.
  - 표시값을 SearchBox 로컬 상태(거울)로 두어 이벤트 안에서 동기적으로 맞추고, 부모 값은 딥링크나 뒤로가기 같은 외부 변경일 때만 채택한다. 우리가 올려보낸 값의 메아리는 무시한다.

- 프롬프트 히스토리 클릭 시 앱 전체가 죽던 문제 + 에러 경계 도입
  - 버튼을 누르면 화면이 통째로 흰 화면이 됐다. IndexedDB에 남아 있던 초기 스키마 기록(action·userText 없음)을 그대로 렌더하면서 예외가 났고, 갤러리엔 경계가 프리뷰용 하나뿐이라 트리 전체가 언마운트됐다.
  - 읽는 길목에서 저장본을 현재 스키마로 정규화하고, fallback을 받는 범용 `ErrorBoundary`와 루트 복구 화면을 신설했다. 앱 루트를 감싸고, 제 데이터원을 각자 읽는 헤더 위젯 셋에 개별 경계를 뒀다. 아이콘 하나의 예외로 헤더 전체가 사라지지 않게 하려는 것이다.
  - 저장된 데이터를 읽는 길목에 정규화가 없으면 스키마가 바뀔 때마다 이런 일이 난다는 게 오늘 여러 번 반복된 교훈이었다.

- 복제에 스켈레톤·완료 토스트 + 컴포넌트 복제는 케밥으로
  - 복제가 너무 빨리 끝나 화면만 바뀌고 "복제됐다"가 안 읽혔다. 최소 1초 대기 동안 목적지 골격 스켈레톤을 덮고, 끝나면 토스트로 원본과 사본 이름을 나란히 남긴다. 이름을 실으려 페이지·흐름 클론 응답에 title/name을 추가했다.
  - 컴포넌트 복제는 헤더에서 케밥 안으로 옮겼다. 컴포넌트는 베껴 변형할 일이 드물어 헤더 한 자리를 늘 차지할 만큼 자주 쓰이지 않는다.

- 페이지 삭제(휴지통) + 이름·설명 즉시 반영 + 편집 칸 폭 정렬
  - 페이지는 파일을 지우지 않고 `pages/.trash/`로 옮긴다. 흐름은 아무도 참조하지 않는 잎이라 unlink로 충분하지만, 페이지는 아직 커밋되지 않았을 수 있는 몇 시간짜리 작업이라 "git에 있으니 괜찮다"가 성립하지 않는다.
  - `deprecated` 같은 플래그 대신 위치를 상태의 단일 진실로 삼았다. 같은 볼륨 rename이라 본문과 히스토리 사이드카가 바이트 그대로 따라가고, `.trash/`는 디렉토리라 활성 페이지 스캔에서 자연히 빠진다. 이 페이지를 쓰는 흐름은 편입 때 박제해 둔 스냅샷으로 계속 재생된다.
  - 이름·설명이 새로고침해야 보이던 문제도 두 갈래로 고쳤다. 레지스트리는 `import.meta.glob(eager)` 정적 배열이라 서버가 엔트리 JSON을 고쳐도 클라 메모리는 그대로인데, HMR 플러그인이 add/unlink만 듣고 change를 안 듣고 있었다. 페이지 플레이그라운드 쪽은 목록 위에 겹치는 팝업이라 닫아도 목록이 재마운트되지 않아서, 쓰기 API가 성공 자리에서 신호를 쏘고 목록이 다시 불러오게 했다.

- 모달이 뜨면 페이지 팝오버가 백드롭 위에 남던 문제
  - 갤러리가 `.z-popover`를 통째로 55로 올려 모달 안 팝오버를 패널 위로 띄우고 있었는데, 그 우회가 모달 밖 팝오버까지 55로 만들고 있었다.
  - Dialog 패널 children을 `OverlayLayerProvider(layer="modal")`로 감싸 디자인 시스템의 레이어 계약에 참여시키고, CSS 우회를 제거했다. 모달 안 팝오버는 스스로 55를 붙고, 모달 밖 팝오버는 모달 마운트 신호를 받아 스스로 닫힌다. 우회로 덮은 것을 계약으로 되돌린 자리다.

- 이름·설명 수정을 ModifyComposer 팝오버로 통합
  - 제자리 편집은 칸마다 따로 저장돼, "이게 무엇인지 다시 쓰기" 한 번이 저장 두 번, 덜컹임 두 번으로 쪼개졌다. 설명 칸도 읽기 줄 수 2줄에 묶여 긴 글을 쓰기 어려웠다.
  - 피드백 작성기 카드를 본떠 제목 input과 설명 textarea를 한 팝오버에 담고 한 번에 저장한다. 제출은 체크 아이콘이다. 이 표면의 일은 "고치기 시작"이 아니라 확정이기 때문이다.
  - 세 헤더가 같은 작성기를 쓰고, 어느 칸을 눌러도 그 자리에 붙어 열린다. 배치는 상수 320을 믿지 않고 폭을 실측한다. 384 카드가 밀려 잘렸기 때문이다.
  - 나중에 표시명 칸은 열자마자 `select()`까지 하도록 했고, 바깥 클릭으로도 닫히게 했다. 여는 쪽 버튼만은 예외로 뒀다. 그 클릭은 재오픈이라 먼저 닫으면 작성기가 다시 마운트되며 적어 둔 값이 날아간다.

- 아바타 크롭 결과가 미리보기 배율·위치와 어긋나던 문제
  - Tailwind Preflight의 `img,video { max-width:100%; height:auto }`가 미리보기 `<img>`에 그대로 걸려, 레이아웃 박스가 뷰포트 200px에 맞춰 축소된 채 그 위에 `scale()`이 곱해졌다. 확정 렌더는 canvas라 natural 크기 기준이었고 두 좌표계가 어긋났다.
  - 인라인 style에 원본 픽셀 width/height와 `maxWidth:none`을 못박아 두 경로를 일치시켰다. 격자 이미지로 예측값과 실제값을 나란히 재서 확인했다.

- ui:valid 유채색 게이트 정리
  - BLOCK 8건이 쌓여 게이트가 막혀 있었는데 성격이 둘로 갈렸다. 7건은 스토리 전용 픽스처였다. 스크립트 머리말이 이미 대상을 "컴포넌트 본체"로 못박고 `*.demo.tsx`와 `*.stories.tsx`를 빼고 있었는데, 픽스처가 쓰는 두 이름만 규칙에 빠져 있었다. 선언된 의도대로 채웠다.
  - 색마다 `meta.tokenExceptions`를 다는 건 답이 아니었다. 그 필드는 "이 색은 정당하다"를 적는 곳이지 "이 파일은 스토리다"를 적는 곳이 아니다. 대상 자체가 아닌 걸 예외로 적으면 이유 칸이 거짓말이 된다.
  - 나머지 1건은 진짜 예외라 기존 장치로 이유와 함께 선언했다. 주석 자율면제는 도입하지 않았다. 주석은 누구나 조용히 빠져나갈 수 있지만 엔트리 선언은 이유가 남고 리뷰에 걸린다.

- 아바타·닉네임 변경이 화면에 즉시·전부 반영되도록
  - 업로드 아바타 URL 경로가 `/avatars/<닉네임>.png`로 고정이라 사진만 바꾸면 URL이 안 변해 브라우저가 옛 이미지를 계속 썼다. `?v=updatedAt`을 붙였다.
  - 닉네임은 `useSyncExternalStore`로 구독하게 바꿨다. localStorage는 같은 탭에 storage 이벤트를 안 쏴서, 저장해도 새로고침 전까지 옛 이름이 남았다.
  - 옛 이름 별칭을 도입해 레지스트리 `createdBy`와 히스토리 `actor`에 박제된 이름을 지금 닉네임·아바타로 해석한다. 다만 git user.name은 사람과 봇이 체크아웃을 공유하므로 이미 독립 레코드가 있으면 흡수하지 않는다.

- 표시명·설명 저장 시 전체 새로고침 제거
  - 수정 작성기로 저장하면 앱이 통째로 다시 뜨느라 한 박자 멈추고 스크롤이나 팝오버 같은 화면 상태가 날아갔다. 원인이 두 겹이었다. 엔트리 JSON이 `import.meta.glob({eager:true})`로 Vite 모듈 그래프에 들어가 있어 accept할 곳을 못 찾고 루트까지 올라갔고, HMR 플러그인도 같은 변경에 스스로 full-reload를 쏘고 있었다.
  - 메타 변경은 모듈이 아니라 데이터라 리로드할 이유가 없다. `hotUpdate` 훅에서 Vite 기본 처리를 가로채고 바뀐 키만 통지해, 받는 쪽이 그 엔트리만 다시 받아 갈아 끼우고 최상단에서 한 번 리렌더한다.
  - 저장 자체도 낙관적으로 바꿨다. 작성기는 서버 왕복을 기다리지 않고 바로 닫히고, 실패하면 디스크 값으로 되돌리고 토스트로 알린다. 표시명과 status를 로컬 state 사본으로 들고 있던 자리도 걷어냈다. 사본이 있으면 밖에서 들어온 변경만 그 화면이 못 따라간다.

- 사용 예제 코드 표현을 두 번 고쳤다
  - 한 줄로 뭉개던 것을 import 문과 JSX 두 줄로 나눴다가, 다음 커밋에서 한 칸 들여쓰기를 없애고 원래 만들어지던 형태(빈 줄 구분)를 그대로 그리게 되돌렸다. 별도 변형이 필요 없었다는 결론이다.
  - 나중에 "사용 예제" 제목도 코드 박스 안에서 밖 독립된 h3로 뺐다. 다른 섹션 제목과 위계가 안 맞아 보였기 때문이다.

- 갤러리 정적 title을 GALLERY로 통일
  - registry 엔트리 add/unlink 시 Vite 풀리로드가 걸리는 dev 전용 동작은 유지하되, `index.html`의 정적 title이 "COMPONENTS GALLERY"로 달라 리로드 순간 탭 제목이 깜빡였다. 마운트 후 세팅하는 값과 맞췄다.

- 표시명 저장 실패 토스트를 경고로, 서버 원문 대신 안내 문구로
  - `working tree dirty for this entry` 서버 원문을 그대로 노출하던 걸 원인별로 갈라 안내 문구로 바꿨다. 2.2초 만에 사라지던 토스트도 warning variant로 6초 유지한다. 사람이 뭔가 조치해야 끝나는 실패라 확인만 하고 넘어가는 토스트와 같은 취급이면 안 된다.
  - `toast()`에 variant와 duration 옵션을 추가하되 기본값을 유지해 기존 30여 호출부는 손대지 않았다. warning과 error는 `role="alert"`로 스크린리더에 놓치지 않게 했다.

- 카드·행 아바타를 생성자 1인에서 전체 기여자로 통일
  - 카드와 행은 최초 생성자 한 명만 보여줬는데 상세 히스토리 타임라인은 이벤트 전체 actor를 집계해 2명 이상이면 겹쳐 보여줬다. 같은 엔트리인데 목록과 상세에서 "몇 명이 다녀갔는지"가 다르게 보였다.
  - 타임라인의 집계 로직을 `contributorsOf`로 뽑아 단일 진실로 삼고, 세 곳이 공유하는 `ContributorAvatars`를 새로 만들었다.

- 마무리 다듬기와 실사용 흔적
  - Selector 트리거에 className 오버라이드를 허용했다. 기본 높이가 옆 컨트롤과 안 맞는 자리에서 덮어쓸 수 있어야 했고, `cn`이 tailwind-merge라 같은 축이면 이 값이 이긴다.
  - 앱 크래시 폴백 화면을 다듬으면서 쓴 `rounded-pill`이 이 프로젝트 Tailwind `@theme`에 정의되지 않은 토큰이라 CSS가 생성되지 않아 버튼이 각지게 렌더됐다. 코드베이스의 실제 관례인 `rounded-full`로 바로 고쳤다.
  - 오늘 만든 기능들로 실제 데이터를 만졌다. accordion과 home-getting-started 계열 엔트리의 표시명·설명을 여러 번 고치고, gnb-snb 페이지를 복제해 사본을 만들고 제목·설명을 정리했다. 닉네임·아바타도 여러 번 저장했다. 기능을 만든 직후 그 기능으로 실 데이터를 만지는 게 오늘의 검증 방식이었다.

## 정리

오늘 이 묶음을 관통한 결정은 하나다. **바꿀 수 없는 것을 억지로 바꾸려 하지 않고, 그 위에 바꿀 수 있는 층을 하나 더 뒀다.** 컴포넌트 `name`은 딥링크와 박제 스냅샷이 가리키는 키라 rename이 과거를 깨뜨린다. 그래서 `displayName`을 덧씌우고 표시하는 자리만 그걸 읽게 했다. 페이지 삭제도 같은 모양이다. `deprecated` 플래그를 늘리는 대신 파일을 `.trash/`로 옮겨 위치 자체를 상태로 삼았다. 플래그는 읽는 쪽 전부가 알아야 하지만 위치는 스캔이 자연히 걸러낸다.

그런데 층을 하나 더 두면 반드시 **그 층이 새는 곳**이 생긴다. 오늘 하루에만 즉시 실행 팝오버 칩, 터미널 run 라벨, 화면 시연 Dock, 배선 머리줄, 목적지 피커가 각각 `displayNameOf` 규약을 건너뛰고 원시 이름을 직접 그리고 있는 걸 발견했다. 규약을 만들었다는 것과 규약이 지켜진다는 건 다른 일이고, 새는 자리는 만들 때가 아니라 쓸 때 하나씩 드러난다. `displayNameOf` 하나로 모아 두길 잘했다고 느낀 건 고치는 게 "그 자리를 이 함수로 바꾸기"로 끝났기 때문이다.

또 하나 반복해서 부딪힌 건 **정규화가 신규 필드를 조용히 버리는 함정**이다. 클론에서 `derivedFrom`, 페이지 편집에서 `description`, 프롬프트 히스토리에서 옛 스키마 기록. 셋 다 "알려진 필드만 다시 조립하는 함수"가 원인이었고, 셋 다 저장은 되는데 읽을 때 조용히 사라지거나 예외를 냈다. 조용한 실패는 알아채는 데 시간이 가장 오래 걸린다. 프롬프트 히스토리는 아예 앱을 흰 화면으로 만들고 나서야 알았고, 그래서 에러 경계를 도입했다. 경계가 없으면 아이콘 하나의 예외가 트리 전체를 언마운트한다.

마지막으로 오늘 두 번 마주친 패턴이 있다. **우회로 덮어 둔 것은 언젠가 반드시 다른 곳을 망가뜨린다.** `.z-popover`를 통째로 55로 올린 CSS 우회는 모달 안 팝오버를 살리려던 건데 모달 밖 팝오버를 백드롭 위에 남겼고, 결국 레이어 계약에 정식으로 참여시켜 우회를 지웠다. 엔트리 JSON을 모듈 그래프에 넣어 둔 것도 비슷하다. 편했지만 저장할 때마다 앱이 통째로 새로고침되는 대가를 치르고 있었고, "메타 변경은 모듈이 아니라 데이터"라고 인정하고 나서야 풀렸다.
