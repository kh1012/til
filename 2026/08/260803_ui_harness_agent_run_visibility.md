# 돌고 있다는 걸 어떻게 보여줄 것인가

> "즉시 생성"을 누르면 화면에 아무것도 안 생겼다. 터미널 독을 직접 열지 않는 한 뭐가 돌고 있는지, 얼마나 걸리는지, 끝나긴 했는지 알 방법이 없었다. 오늘은 이 하나를 파고들면서 대기 카드, 좌하단 트레이, 접수 토스트, 사용자 말풍선, 실행 옵션까지 붙였다. 상시 노출되는 UI라 SSE 이벤트 폭주를 어떻게 견딜지가 처음부터 설계에 들어갔다.

## 배경

에이전트에 일을 시키는 길은 이미 여러 갈래로 뚫려 있었다. 컴포넌트 수정, 분할, 생성, 흐름 생성, 페이지 피드백까지 다섯 자리에서 spawn을 부른다. 그런데 눌렀을 때 사용자에게 돌아오는 신호가 없거나, 있어도 터미널 독을 통째로 여는 방식이었다. 독은 화면을 크게 덮는 Dialog라 켜 두기 어렵고, 닫으면 진행 상황이 통째로 사라졌다.

여기에 두 번째 문제가 겹쳤다. 로그가 전부 에이전트 출력이라 "내가 뭘 시켰는지"가 어디에도 안 남았다. 며칠 뒤에 로그를 다시 열면 무엇에 대한 답인지 알 수 없다.

세 번째는 속도였다. 간단한 요청에도 전체 검증 게이트가 돌아 몇 분씩 걸렸다. 무거운 검증이 필요한 요청과 한 줄 고치는 요청이 같은 값으로 도는 게 문제였다.

## 핵심 내용

### 개별 작업 기록 (시간순)

- 터미널 로그 줄의 톤 분리
  - 도구 이름과 경로·동사를 두 span으로 갈라 뒤쪽을 옅은 회색으로 내렸다. 줄 전체가 톤 색이면 눈이 갈 곳이 없어 "무슨 도구였나"가 안 읽힌다. 경로는 길고 동사는 늘 같은 값이라 더 그렇다.

- 즉시 생성 진행 상태: 대기 카드·대기 상세·터미널 바로가기
  - 컴포넌트와 페이지는 대기 카드를 목록 위에 깐다. 이 둘은 이름을 에이전트가 정하므로 제출 시점엔 가리킬 대상 자체가 없다. 카드를 누르면 상세 골격이 깔린 대화상자가 열리고 거기서 터미널로 바로 갈 수 있다.
  - 흐름은 뱃지만 붙인다. 흐름 생성은 파일을 먼저 만들고 에이전트가 연결만 채우므로 목록에도 상세에도 진짜 내용이 이미 있다. 그 위에 스켈레톤을 씌우면 있는 것을 가짜로 덮는 셈이다.
  - 대상 이름을 따로 들고 다니지 않는다. run의 done 이벤트를 파싱하면 만들어진 이름이 나와서 "열기" 링크까지 run 하나에서 만들어진다.
  - 완료돼도 자동으로 넘어가지 않는다. 로그를 읽는 중이거나 여러 개를 동시에 돌렸을 때 화면이 제멋대로 바뀌면 방금 보던 것을 잃는다. 실패한 카드도 남긴다. 조용히 사라지면 무엇이 왜 안 만들어졌는지 알 방법이 로그를 뒤지는 것뿐이다.
  - 끝난 run을 언제까지 붙잡을지는 시각으로 판단한다(10분). 봤는지 여부를 state로 들면 목록을 떠났다 오는 순간 리셋돼 결과가 사라진다. 끝나자마자 치우면 "생성됨, 열기"를 볼 틈이 없다.

- 터미널 로그 hover 색 완화 + run 라벨에 표시명 반영
  - 도구 줄 세 span을 전부 강조색으로 바꾸고 있었다. 채도 높은 색이 튀는 것도 문제지만, 도구 이름과 경로의 색 구분이 hover 때만 사라져 위계가 무너지는 게 더 컸다. 색은 그대로 두고 줄 전체의 투명도만 낮춰 각자의 색을 지킨 채 "눌린다"만 전한다.
  - run 라벨이 원시 이름을 그대로 보여줘 카드·상세와 다른 이름으로 불리고 있었다. 만들 때가 아니라 그릴 때 표시명으로 바꾼다. 라벨은 spawn 시점에 서버로 박제되는데 표시명은 나중에 또 바뀔 수 있어서, 라벨에 박아 두면 그 순간부터 옛 이름으로 굳는다. 원시 이름은 `contextHref`에 남아 있으므로 그릴 때마다 다시 푼다.
  - 완료 문장을 고르는 함수에는 적용하지 않았다. 그건 이름을 보여주는 게 아니라 접미사로 문장을 고르는 함수라 원본 라벨이 들어가야 한다.

- 최소화 버튼 + 좌하단 실행 트레이
  - 최소화는 패널을 접고 좌하단 목록으로 줄인다. 목록이 곧 접힌 터미널이다. 닫기는 목록까지 치운다. "이제 안 볼래"는 명시적인 선택이고 새 run이 뜨면 다시 나타난다. 두 버튼이 같은 일을 하면 둘 중 하나는 있을 이유가 없다.
  - 이 트레이는 run이 도는 내내 떠 있으므로 SSE 이벤트 폭주를 정면으로 맞는다. 네 가지를 미리 막았다. (1) `events` 배열을 읽지 않는다. `run-event` 프레임이 이벤트마다 배열을 통째로 새로 만들어 run 참조를 바꾸므로, 쓰는 필드만 뽑고 값이 같으면 이전 배열 참조를 그대로 재사용해 행 `memo`가 걸리게 했다. (2) 경과 시간 타이머가 호출마다 `setInterval`을 만들고 있어서 모듈 티커 하나로 모았다(구독자가 0이면 멈춘다). (3) 표시명 조회가 엔트리 123개를 선형 스캔하므로 메모이즈했다. (4) 완료분은 대기 카드와 같은 규칙으로 정리하고 최대 5줄까지만 펼친다. 같은 일이 화면 두 곳에서 다른 시간만큼 남으면 어느 쪽이 맞는지 모른다.
  - body로 포털한다. 헤더 안에서 렌더되는데 헤더에 `backdrop-blur`가 걸려 있어 필터가 잡힌 조상이 `position: fixed`의 기준 상자가 된다. 포털 없이는 `bottom-4 left-4`가 뷰포트가 아니라 헤더 기준으로 잡혀 화면 위쪽에 붙었다(실측 y=-1).

- 비활성 툴팁 문구 정리
  - "이미 실행 중 — 터미널에서 이어서 요청하세요"의 em dash를 하이픈으로 바꿨다가, 곧 뒤 문장을 아예 빼고 "이미 실행 중입니다."로 축약했다. 막힌 이유만 짧게 말한다.
  - 한 곳만 고치면 같은 문구가 화면마다 다른 글자를 쓰게 되므로, 이 문자열을 각자 들고 있던 세 곳을 함께 맞췄다.

- 즉시 실행은 토스트로 알리고 진행 목록은 상시 노출
  - spawn 직후 터미널 독을 자동으로 열지 않는다. 화면 절반이 덮이고 그 run의 로그 시점까지 끌려가 매번 독을 닫아야 했다. 접수 사실은 하단 중앙 토스트 한 줄로 알린다. 다섯 spawn 자리가 공통 헬퍼를 쓴다.
  - 독 헤더의 최소화 버튼은 제거했다. 몇 시간 전에 만든 것인데, 닫기가 이미 "패널만 닫고 진행 목록은 남긴다"라서 둘이 같은 일을 하고 있었다. 만들 때 세운 구분이 다음 변경에서 무의미해진 자리다.

- 터미널 로그에 사용자 말풍선 (클라이언트 절반, 이어서 서버 절반)
  - 그 턴의 사용자 원문과 뱃지로 붙인 참조를 `user` 이벤트로 받아 오른쪽 정렬 말풍선으로 그린다. 참조는 원시 이름으로 저장하고 그릴 때 표시명으로 푼다. run 라벨과 같은 원칙이다.
  - 클라이언트를 먼저 넣을 때는 서버가 아직 `user` 이벤트를 만들지 않아 화면에 안 보이는 상태로 커밋했다. 서버 쪽은 dev 서버 재시작이 필요해서 실행 중인 세션이 끝난 뒤 이어 붙였다.
  - 서버 절반에서는 CLI stdout에 없는(사람이 적은) 입력이라 서버가 직접 넣는 유일한 이벤트 종류가 됐다. 첫 턴은 run 등록 직후, 이어지는 턴은 그 자리에서 쌓고, 큐에 눌러 뒀다 자동으로 도는 턴도 실행 시점에 같은 말풍선으로 붙는다.
  - 이어지는 턴에 사용자 원문이 오면 완성 프롬프트 이벤트는 안 남긴다. 같은 요청이 한 줄과 수백 줄로 두 번 찍히던 걸 없앴다. 안 오면(구 클라이언트) 예전 그대로다.
  - 상한을 뒀다. 문장 4000자, 참조 20개에 각 120자. 붙여넣기 한 번에 SSE 프레임이 부푸는 걸 막는다.
  - 나중에 말풍선이 10줄을 넘으면 접고 펼치기 버튼을 붙였다. `\n` 개수가 아니라 실제 렌더된 줄 높이로 오버플로를 판정한다. 긴 URL이 여러 줄로 감기는 경우가 있어서다.

- 완료된 실행 줄을 눌러 결과로 이동하고 소비 상태를 영속화
  - 접힌 터미널의 끝난 줄은 눌러도 목록에서 사라지기만 해서 "그래서 뭐가 바뀌었나"를 보려면 독을 다시 열어야 했다. 이제 끝난 줄은 결과로 가는 링크다.
  - 소비한 run id를 localStorage에 저장한다. 메모리 state였을 땐 강제 새로고침마다 완료 목록이 통째로 돌아왔다. 저장 규칙(중복 무시, 최근 우선, 상한 300, 손상·부재 스토리지 안전)에 단위 테스트를 붙였다.

- 즉시 실행 검증 수준·모델·effort를 Composer에서 고정 설정
  - 검증 수준 1/2/3을 도입하고 기본을 1로 뒀다. 서버가 spawn 길목에서 프롬프트에 한 번만 지시를 덧붙인다. 레벨 1은 가이드의 하드룰("위반 시 완료 거부")과 브라우저 자동화까지 명시적으로 덮어써야 실제로 생략된다.
  - 모델과 effort는 CLI 플래그로 전달한다. claude는 `--model`/`--effort`(low~max, `claude --help` 실측), codex는 `-m`/`-c model_reasoning_effort=`(minimal~xhigh, 공식 문서 기준으로 미실측). 값 집합이 달라 설정을 CLI별로 분리 저장한다.
  - 설정은 localStorage에 영구 저장하고, spawn 요청에 싣는 일은 `postAgentSpawn`이 전담한다. 호출부가 흩어져 있어 각자 읽게 하면 한 곳만 빠뜨려도 설정이 안 먹는다.
  - 드롭다운은 로컬 absolute로 뒀다. 상위 팝오버의 outside-click 오인을 피하려는 것이다.

- 작성기 표면 다듬기
  - 옵션 팝오버를 1.2배로 넓혀 참조 뱃지와 긴 프롬프트가 한 줄에 더 들어가게 하고, 좌하단 옵션 버튼 배경을 상시 pill로 바꿨다. `bg-st-muted`는 라이트 스킨에서 배경과 명도차가 없어 안 보이길래 foreground 저알파로 대체했다. 기존 피드백 작성기가 이미 같은 사정으로 우회하고 있었다.
  - 붙여넣기 표현은 세 번 고쳤다. 처음엔 잠깐 떴다 사라지는 줄 수 뱃지, 다음엔 값 자체에 `[N줄 붙여넣음]` 자리표시자를 접어 넣는 방식(원문은 ref에 보관하다 제출 시 되돌린다), 마지막엔 `[붙여넣은 텍스트 #N +N줄]` 형식으로 바꿔 한 글에서 여러 번 붙여넣어도 구분되게 했다. 뱃지를 버린 이유는 아이콘이 붙었다 사라지며 레이아웃 시프트가 났기 때문이다.

- Thinking Shimmer에 effort·검증 수준 표시
  - 모델만 보이던 진행 표시줄이 "(2m 2s · opus-5 · high · 검증2)"가 됐다. effort는 이제 우리가 spawn 시점에 직접 넘긴 값이라 신뢰하고 보여줄 수 있다. 예전엔 CLI가 보고하지 않아 표시하지 않았다.
  - 검증 수준은 그동안 프롬프트에만 반영되고 run에 저장되지 않았다. `AgentRun`에 `verifyLevel`을 추가해 "이 run이 실제로 뭘로 돌았는지"를 남긴다. 전역 설정이 아니라 spawn 시점 값이라 이후 설정을 바꿔도 이미 뜬 run 표시는 안 바뀐다.
  - 조합 로직을 컴포넌트에서 분리해 mount 없이 단위 테스트로 검증했다.

- 실행중 카드 링을 유리판 sheen으로, 제목엔 shimmer
  - 단순 링에서 유리판이 스치는 sheen 오버레이로 바꾸고, 제목 옆엔 상시 초록 점을 뒀다. 제목 글자 자체도 `background-clip:text` 기법으로 반짝이되 피크 색을 잉크가 아니라 sheen과 같은 흰빛으로 맞췄다. 면과 점과 제목이 같은 색 언어로 "지금 이 카드가 실행 대상"임을 말하게 하려는 것이다.

- 로그 hover를 opacity 톤으로 통일
  - hover 강조를 인디고 글자색에서 opacity로 통일해 이웃 컴포넌트와 표현 방식을 맞췄다.
  - 4줄 안에 다 들어가 클릭해도 무변화인 짧은 줄은 hover와 cursor-pointer를 제거했다. `scrollHeight`로 잘림 여부를 판정한다. 눌러도 아무 일 없는데 누를 수 있는 것처럼 보이면 안 된다.

- 실행 중 대기 프롬프트 여러 개 순차 처리
  - 대기 프롬프트가 run.id당 단일 객체라 실행 중 두 번째 입력을 하면 첫 번째가 조용히 덮어써졌다. 서버 run 큐와 같은 문제인지 먼저 확인했는데 별개였다. 이건 클라이언트 상태이고, 동시 슬롯 큐잉이 아니라 "다음 턴 자동 이어달리기" 슬롯이다.
  - 배열로 바꿔 done이나 error가 될 때마다 맨 앞부터 하나씩 소진한다. 작성기 UI도 "대기 중 · {text}" 한 줄에서 "대기 1", "대기 2" 목록 표시로 바꿨다.

- 자산과 스모크 테스트
  - Claude와 Codex 아이콘 SVG를 정적 자산으로 복사해 뒀다. 아직 참조하는 곳은 없고 CLI 셀렉터에서 로컬 자산으로 쓸 자리를 미리 마련한 것이다.
  - "아무것도 하지마" 요청으로 즉시 실행 무변경 경로를 확인한 스모크 테스트 기록도 남겼다.

## 정리

이 묶음 전체가 답하려던 질문은 하나다. **진행 중인 일을 화면 어디에 얼마나 오래 두어야 하는가.**

처음엔 "누르면 독을 연다"였는데 그게 최악이었다. 화면 절반이 덮이고 로그 시점까지 끌려가 매번 닫아야 했다. 그다음이 "대기 카드를 목록 위에 깐다"였고, 이건 컴포넌트·페이지처럼 아직 대상이 없는 경우엔 맞았지만 흐름처럼 이미 진짜 내용이 있는 경우엔 있는 것을 가짜로 덮는 꼴이었다. 그래서 흐름은 뱃지만 붙였다. 결국 정착한 건 **접수는 토스트, 진행은 좌하단 트레이, 상세는 독**이라는 3단 구조인데, 이건 "얼마나 방해할 것인가"를 세 단계로 나눈 것이다.

같은 하루 안에서 만든 걸 곧바로 지운 자리도 있다. 독 헤더의 최소화 버튼은 만들 때는 닫기와 다른 일이었는데, 트레이가 상시 노출로 바뀌면서 닫기가 이미 "패널만 닫는다"가 되어 둘이 같은 일이 됐다. 몇 시간 전 결정이 다음 결정에 의해 무의미해지는 걸 그대로 인정하고 지우는 게 맞았다.

**상시 노출은 성능 문제를 필연적으로 데려온다**는 것도 이번에 몸으로 알았다. 트레이는 run이 도는 내내 떠 있으니 SSE 프레임을 전부 맞는다. `events` 배열을 읽기만 해도 값이 하나도 안 바뀐 행이 전부 다시 그려지고, 경과 시간 훅이 호출마다 타이머를 만들면 N행에 N개 타이머가 붙고, 표시명 조회는 엔트리 123개 선형 스캔이라 행마다 렌더마다 부르면 N×123이 된다. 셋 다 기능 자체와는 무관하고 "이 UI가 상시 떠 있다"는 사실에서만 나오는 비용이다. 만들고 나서 느려진 걸 고치는 대신 만들 때 미리 막은 게 이번엔 잘한 선택이었다.

마지막으로 **표시명은 만들 때가 아니라 그릴 때 푼다**는 원칙이 여기서도 반복됐다. run 라벨도, 말풍선의 참조 뱃지도 마찬가지다. 저장 시점에 이름을 박제하면 나중에 이름이 바뀌었을 때 그 순간부터 옛 이름으로 굳는다. 원시 이름만 들고 다니다가 그릴 때마다 지금 이름으로 다시 푸는 게 유일하게 안 어긋나는 방법이었다.
