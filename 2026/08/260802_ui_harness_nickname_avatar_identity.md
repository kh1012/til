# git config가 아니라 사람이 고른 이름

> 하네스의 모든 기록에는 "누가 했는지"가 붙는데, 그 값이 git config에서 먼저 왔다. 그래서 여러 사람이 같은 dev 서버를 띄우거나 회사 계정 이름이 팀 안에서 안 통하면 기록의 주인이 흐려졌다. 오늘 새벽에 한 일은 그 우선순위를 뒤집고, 뒤집은 이름에 얼굴을 붙여 화면 곳곳에서 알아볼 수 있게 만든 것이다.

## 배경

하네스는 컴포넌트·페이지·흐름에 무슨 일이 있었는지를 히스토리로 쌓고, 카드마다 생성자를 적는다. 이 actor 값을 정하는 `resolveActor`가 git config `user.name`을 먼저 읽고, 실패했을 때만 로컬에 저장한 이름으로 폴백했다.

문제는 그 우선순위가 실제 사용 순서와 반대라는 것이었다. git 설정은 회사 계정이라 팀 안에서 서로를 못 알아보는 이름이기 쉽고, 무엇보다 사용자가 직접 입력한 값이 있는데도 그게 진다. "직접 적었는데 왜 안 바뀌지"가 되는 구조다.

여기에 하나 더 겹쳐 있었다. 이름을 처음 입력받는 모달은 최초 1회 이후 다시 열 방법이 아예 없었다. 잘못 적으면 고칠 길이 없다.

## 핵심 내용

### 개별 작업 기록 (시간순)

- 이름 입력 모달 문구·레이아웃 다듬기
  - 문구를 "이름을 입력해주세요"로 바꾸고, 설명을 문장 단위로 줄바꿈해 핵심 구절(누가 했는지·git 설정·여기 입력한 이름)만 굵게 강조했다. 각 문장이 한 줄에 들어가도록 모달 너비도 `max-w-sm`에서 `max-w-lg`로 넓혔다.
  - 별도 "저장" 버튼을 두는 대신 공용 `ChatInput`을 재사용했다. 우측 원형 전송 버튼이 값이 비어 있으면 아예 없고, 첫 방문 자동 포커스와 Enter 제출이 컴포넌트 자체 동작으로 딸려 온다. 입력만으로 저장까지 끝난다.
  - `@maxflow/ui/chat-input`은 package.json exports에 명시 항목이 없어 wildcard 폴백으로 잡히는 탓에 tsc가 못 찾는다. Tooltip·Badge와 같은 canonical shim 패턴으로 `ui-shims.d.ts`에 타입 표면을 선언했다.

- 닉네임 우선순위 반전 + "이름"에서 "닉네임"으로 리네임
  - 오늘의 중심 결정이다. 이제 닉네임(로컬 저장, `x-harness-nickname` 헤더)이 있으면 그게 항상 이기고, 없을 때만 git으로 폴백한다.
  - 동시에 `user-*` 명명을 `nickname-*`로 통째로 옮겼다(`user-identity.ts`에서 `nickname.ts`, `UserNameModal.tsx`에서 `NicknameModal.tsx` 등). 실명이 아니어도 되는 자유로운 별명이라는 걸 코드 이름과 문구 양쪽에 반영했다.
  - 검증은 curl로 실제 상태변경 API를 왕복으로 쳤다. 헤더값이 git보다 우선 적용되는지, 헤더가 없을 때 git으로 정상 폴백하는지 둘 다 확인했고, 그 과정에서 실제 레지스트리에 남은 테스트 커밋 4건(`toolbar-expandable` 상태 변경과 히스토리 적재)은 `git revert`로 정리했다.

- 상단 네비 아바타 팝오버 + git 설정 요약
  - `lib/git-identity.ts`를 새로 두어 부팅 시 1회 git config `user.name`/`user.email`을 읽고 `GET /api/whoami`로 노출한다. 기존 `computeDecidedBy`는 actor 폴백용 단일 문자열이라 email까지 담을 수 없어 따로 뒀다. git 프로세스가 하나 더 뜨지만 부팅 1회뿐이라 무시할 만하다.
  - 헤더 도움말 버튼 옆에 아바타 버튼을 붙였다. 누르면 닉네임과 git 설정 요약이 뜨고, "닉네임·아바타 변경"으로 모달을 다시 열 수 있다. 최초 1회 이후 재입력 방법이 없던 문제가 여기서 풀린다.
  - 헤더에 처음 생기는 "버튼에서 패널" 케이스라 로컬 드롭다운을 손수 만들지 않고 canonical `@maxflow/ui/popover`를 그대로 썼다. 포털·바깥클릭·Escape·뷰포트 플립이 전부 들어 있다. `AgentChoiceSelector`류 로컬 드롭다운은 다른 포털 팝오버 안에 중첩될 때만 필요한 예외 처리라 헤더 최상위 트리거엔 해당하지 않는다.

- 아바타 선택(템플릿/업로드+크롭) + 서버 공유 저장
  - 닉네임 모달에 `AvatarPicker`를 얹었다. 보편적인 8색 원형 스와치에서 고르거나, 이미지를 올려 `AvatarCropper`로 잘라 쓴다. 레포에 크롭 라이브러리가 없어 canvas 기반 팬/줌 원형 크롭을 직접 구현했다.
  - 뷰포트 자체를 `rounded-full`로 둬서 보이는 원이 곧 실제 결과가 된다. CSS 미리보기와 canvas 확정 렌더가 같은 순서로 변환을 합성하므로 둘이 어긋날 여지가 없다.
  - 서버는 닉네임에서 아바타로 가는 맵을 `resolved-created-by.json`과 같은 위치(`registry/nicknames.json`)에 저장하고, 다른 registry 쓰기 API와 같은 패턴으로 커밋한다. 다른 사람이 pull 받아도 보이는 공유 메타데이터이기 때문이다.
  - 업로드 이미지는 JSON에 data URL을 통째로 넣지 않고 `public/avatars/<slug>.png`로 저장해 정적 경로만 남긴다. 브라우저 캐시가 정상 동작하고 JSON이 base64로 부풀지 않는다.
  - 공용 `Avatar`에 `style` prop을 추가했다. 사용자가 고른 임의 색상은 런타임에 만든 Tailwind 클래스(`bg-[${color}]`)로는 JIT가 정적으로 못 읽어 안 먹힌다. 인라인 스타일 통로가 필요했고, 순수 추가라 기존 소비처엔 영향이 없다.
  - 여기서도 브라우저로 템플릿 선택·업로드·크롭·저장 전 과정을 밟고 `nicknames.json`과 `public/avatars/*.png` 정적 서빙까지 curl로 확인했다. 검증 중 실제 저장돼 커밋된 테스트 닉네임 3건은 모두 revert로 되돌렸다.

- 히스토리 타임라인에 닉네임 아바타 노출
  - 컴포넌트·페이지 상세 히스토리의 각 줄 actor 이름 앞에 작은 아바타를 붙였다. `lib/use-nickname-avatars.ts`가 `GET /api/nicknames`를 SPA 세션당 1회만 fetch해 모듈 스코프 캐시로 공유한다. 등록 안 된 이름은 `Avatar` 자체 이니셜 폴백이라 빈 자리처럼 보이지 않는다.
  - "히스토리" 제목 옆에는 그 엔트리를 거쳐간 전체 기여자를 `Avatar.Group`으로 겹쳐 보여준다. 개별 이벤트 줄은 actor가 항상 1명이라 구조적으로 겹칠 수 없으므로, "여러 명이 스쳐 갔다"는 신호는 이 집계 자리에서만 의미가 있다. 기여자가 1명뿐이면 숨긴다.

- 닉네임 모달 레이아웃 재구성 + pilled 통일 + 대비 색상
  - Discord·Slack류 "프로필 만들기" 온보딩(큰 아바타가 시선을 먼저 잡고 그 아래 이름 입력이 다음 순서로 읽히는 배치)을 참고해 순서를 뒤집었다. 3줄짜리 굵은 설명을 한 줄로 줄이고 아바타 피커를 위쪽에 크게 배치해 "지금 뭐부터 해야 하는지"가 한눈에 들어오게 했다.
  - 닉네임 입력을 `FeedbackComposer`류 작성기와 같은 "테두리 없이 배경만 살짝 진한" 표면으로 맞췄다. `ChatInput`에 `hideFocusRing`을 새로 더해(기존 `hideSubmitButton`과 같은 보이콧 프롭 패턴) 자동 포커스 시 뜨는 네온 링을 껐다. 열리자마자 포커스되는 화면의 유일한 입력이라 그 표시가 오히려 테두리처럼 튀어 보였다. 기본값이 false라 기존 소비처엔 영향이 없다.
  - 버튼을 전부 `rounded-full`로 통일하고, 템플릿 색상 스와치는 조금 줄였다. 선택 시 체크와 미리보기 이니셜의 글자색은 배경색의 WCAG 상대휘도로 계산해 검정과 흰색 중 대비가 높은 쪽을 자동으로 고른다(`lib/avatar.ts`의 `contrastTextColor`). 노란 배경에 흰 글자처럼 안 보이던 조합이 사라졌다.
  - 이어서 모달 설명 문단도 마침표 기준 두 줄로 강제 줄바꿈했다. 흐름 삭제 확인 모달 등에서 이미 쓰던 것과 같은 패턴이다.

- "즉시 실행" CLI 설치 여부 탐지 + 미설치 선택지 비활성화
  - `AgentChoiceSelector`가 claude/codex를 정적 배열로 나열만 해서, 이 dev 서버 머신에 그 CLI가 실제로 있는지와 무관하게 항상 둘 다 고를 수 있었다. 없는 걸 고르면 spawn 시점에야 조용히 실패했다.
  - `lib/agent-availability.ts`가 부팅 시 1회, 각 어댑터의 `buildSpawnArgs`가 실제 쓰는 cmd에 `--version`을 던져 PATH 존재를 확인한다. which/where 대신 cross-spawn을 쓴 이유는 이 레포가 실제 spawn에 cross-spawn을 쓰는 이유와 같다. Windows에서 `.cmd` 확장자 같은 걸 셸 없이도 정확히 해석해준다. ENOENT만 "없음"으로 보고 그 외 실패(플래그 미지원 등)는 "있음"으로 친다.
  - `GET /api/agent/available`로 노출하고 셀렉터가 마운트 시 1회 fetch해 미설치 CLI를 비활성화한다(툴팁 "설치되지 않음"). fetch 전에는 낙관적으로 전부 가능하다고 가정한다. 잠깐이라도 실제로는 있는 선택지를 막는 게 더 나쁘기 때문이다.
  - 이 머신엔 둘 다 설치돼 있어 브라우저로는 "평소와 동일하게 둘 다 활성화" 케이스만 라이브로 봤고, 나머지는 코드 리뷰와 curl로 검증했다.

- 카드 하단 영역을 카테고리 뱃지·닉네임 아바타로 전환
  - 컴포넌트 갤러리(카드/리스트 뷰)와 페이지 플레이그라운드 카드 하단의 "카테고리 · @생성자" 평문을 Badge와 Avatar로 교체했다. 생성자 아바타는 히스토리와 같은 닉네임 시스템에서 조회한다.
  - 닉네임 텍스트는 아바타 호버 시 툴팁으로만 노출한다. 카드에서 이름 문자열은 늘 자리를 많이 먹는데 실제로 필요한 건 "누구인지 구분"까지다.

## 정리

오늘 새벽 작업을 관통한 건 **직접 적은 값이 추론한 값을 이겨야 한다**는 원칙이다. git config는 시스템이 대신 추측해준 이름이고 닉네임은 사람이 이 도구를 위해 고른 이름인데, 원래 코드는 추측을 먼저 믿고 있었다. 폴백 순서 한 줄을 뒤집는 변경이지만 의미는 "기록의 주인이 누구인가"를 바꾸는 일이었다. 이런 우선순위는 처음 구현할 때 아무 근거 없이 정해지고, 나중에 뒤집기 전까지 아무도 의심하지 않는다.

**이름을 바꾸는 김에 코드의 이름도 같이 바꾼 것**도 의도적이었다. `user`를 `nickname`으로 옮기지 않았다면 "실명일 필요 없다"는 결정이 UI 문구에만 남고 코드에는 안 남는다. 반년 뒤에 이 파일을 여는 사람은 문구를 안 보고 파일명을 본다.

**공유할 것과 로컬에 둘 것을 가른 자리**도 기록해 둘 만하다. 닉네임 자체는 브라우저 로컬에 있어야 한다(각자 다르니까). 그런데 닉네임에서 아바타로 가는 맵은 서버에 있고 커밋된다. 히스토리에 남은 남의 이름 옆에 그 사람 얼굴이 떠야 하기 때문이다. "내가 누구인지"는 로컬이고 "누가 무엇으로 보이는지"는 공유다. 같은 기능처럼 보여도 저장 위치가 다르다.

크롭을 직접 만들면서 얻은 교훈은 **미리보기와 확정 렌더가 같은 순서로 변환을 합성해야 한다**는 것이었다. CSS transform과 canvas drawImage는 표현 수단이 완전히 다르지만, 팬과 줌을 적용하는 순서가 같으면 결과가 어긋나지 않는다. 뷰포트를 원으로 잘라 두어 "보이는 게 곧 결과"가 되게 만든 것도 같은 이유다. 미리보기가 결과와 다르면 사용자는 저장을 눌러 보고 나서야 알게 된다.

마지막 CLI 탐지는 성격이 다른 일이지만 같은 결의 문제였다. **고를 수 있게 해 두면 사용자는 그게 가능하다고 믿는다.** 설치도 안 된 에이전트를 선택지에 그대로 두고 spawn 시점에 조용히 실패하게 두는 건, 실패를 사용자가 발견하는 시점만 뒤로 미루는 것이다. 다만 fetch 전 낙관적 가정은 반대 방향으로 뒀다. 확인이 끝나기 전에 막으면 멀쩡한 선택지를 잠깐이라도 못 쓰게 되는데, 그건 잘못된 선택지를 잠깐 열어 두는 것보다 나쁘다.
