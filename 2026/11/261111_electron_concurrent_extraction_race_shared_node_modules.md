# 같은 node_modules를 공유하는 E2E 슬롯에서 Electron 바이너리 추출이 동시에 일어나 EEXIST로 실패하는 문제

> PLUGIN_BUILDER_E2E_SLOT으로 포트를 슬롯별로 나눠 병렬 E2E를 돌렸는데, 포트는 안 겹쳐도 같은 워크트리의 node_modules/electron은 모든 슬롯이 공유한다. 두 테스트가 동시에 뜨면 Electron.app 추출이 겹쳐 두 번째 테스트가 `EEXIST (os error 17)`로 죽었다.

## 배경

Plugin Builder E2E는 `PLUGIN_BUILDER_E2E_SLOT` 환경변수로 슬롯(1, 2, 3...)을 나눠 포트 충돌 없이 여러 테스트를 동시에 돌리는 구조다. 슬롯별 포트 분리는 check-fast.sh에서 여러 워크트리·여러 기능을 병렬로 검증할 때 쓰인다. 그런데 `agent-backend.spec.ts`가 같은 슬롯에서 두 번째로 실행될 때만 간헐적으로 실패하는 현상이 나왔다.

## 핵심 내용

- 실패 로그: `failed to create directory '.../node_modules/electron/dist/Electron.app': File exists (os error 17)`
- 슬롯 메커니즘은 **포트**만 분리한다. 같은 워크트리 안의 모든 테스트는 여전히 같은 `node_modules/electron`을 공유한다.
- `app.launch()` 시점에 Electron 바이너리가 아직 추출되지 않은 상태면, Playwright/Electron이 그 자리에서 `electron/dist/Electron.app`을 추출한다.
- 이 추출은 테스트별 포트 할당보다 먼저 일어난다. 두 테스트가 거의 동시에 `app.launch()`를 호출하면 둘 다 같은 디렉토리에 추출을 시도하고, 먼저 디렉토리를 만든 쪽만 성공, 나머지는 `EEXIST`로 실패한다.
- 단독으로 테스트를 돌리면 추출이 한 번만 일어나므로 재현되지 않는다 — check-fast.sh처럼 여러 슬롯이 동시에 뜰 때만 나타난다.
- 해결 방향: (1) 병렬 테스트 시작 전에 Electron을 미리 한 번 추출해 두거나, (2) 추출 구간에 lock 파일을 걸어 직렬화하거나, (3) 슬롯마다 Electron을 워크트리 공유가 아닌 슬롯 전용 위치로 추출.

## 정리

슬롯 기반 분리는 "포트가 안 겹친다"만 보장하지, 그 슬롯들이 공유하는 다른 리소스(여기선 node_modules 안의 바이너리 설치 디렉토리)까지 분리해주지는 않는다. 병렬 실행 설계를 할 때는 분리한 축(포트)과 실제로 경합이 일어나는 축(파일시스템 쓰기)이 같은지 따로 확인해야 한다. 간헐적이고 재현이 "동시 실행에서만" 되는 E2E 실패는 테스트 로직보다 공유 리소스 경합을 먼저 의심하는 게 맞다.
